작성: 2026-11-04 · Issue #15 / PR #19 · Android·iOS·React Native·Flutter·WebView 공통 기준

## 1. 기존 명세와의 관계

이 문서는 화면 구조·흐름·상태·검토 기준을 정한다. API·금액·인증·권한의 기능 계약은 [서비스 명세](service.md)를 재사용한다. 기존 구현은 관찰 근거이며 이 초안의 정답이나 전체 완료 증거로 취급하지 않는다.

| 재사용 근거 | 이 문서에서 참조할 내용 |
| --- | --- |
| [서비스 F01·F02](service.md#f01--인증세션) | 로그인·세션·내 정보·탈퇴. 권한·CSRF·회원 데이터 격리 유지 |
| [서비스 F03](service.md#f03--종목가격환율) | 국내/미국 종목·ETF 검색, 최근 저장 종가, 환율과 실제 기준일 |
| [서비스 F04·F05](service.md#f04--포트폴리오-평가-계산) | 평가·부분 계산·거래 원장·조회/저장 구분·결과 불명 |
| [서비스 F08·F09](service.md#f08--뉴스와-뉴스-부가-분석) | 발행 뉴스·상세·분류·검색. 초안/비발행 콘텐츠 미노출 |
| [Android 적용 명세](android-native/portfolio-design.md) | 기존 탐색 구현·검사 경계. 최신 공통 결정은 이 문서와 대조 |
| [원본 웹 근거·토큰](../docs/design/2026-11-04-web-reference/README.md) | 원본 코드/자산·실제 두 폭 캡처·반응형 관찰 |
| [공통 UI 상태 지식](../knowledge/wiki/shared/ui-state-navigation.md) | 입력 초안·요청 수명·뒤로 가기·접근성의 기존 이식 지침 |

우선순위: 최신 사용자 확정 결정 → 서비스/대상 기능 계약 → 승인된 UI/UX 명세·시안 → 구현. 계약 충돌은 구현으로 임의 해소하지 않고 결정 항목으로 남긴다.

## 2. 확정된 화면 틀과 범위

**사용자 확정:** 상단에 항상 보이는 검색창 → 독립된 화면 본문 → 하단 `포트폴리오 · 이슈 · 내 계정` 순서다. 첫 화면은 포트폴리오다. 검색은 별도의 네 번째 하단 탭으로 만들지 않는다. 리그는 넣지 않는다.

- 모바일: 상단 검색과 하단 3탭을 고정하고 본문만 스크롤한다. 마지막 내용·입력·버튼이 시스템 영역이나 하단 바에 가리지 않아야 한다.
- 다섯 클라이언트는 탭 이름·순서·검색의 의미·상태 용어를 공유한다. OS 고유 위젯·입력·뒤로 가기 표현은 다를 수 있다.
- 넓은 화면도 세 목적지를 유지한다. 원본의 본문/소식 배치 전환은 재사용하되 하단 바를 rail/sidebar로 바꾸는 것은 이번 확정에 포함하지 않는다(D04).
- 포트폴리오와 거래 입력을 대표 상세화 범위로 삼는다. 이슈·계정은 이번 초안에서 탐색/진입·공통 상태를 정하고 세부 화면은 후속 명세로 확장한다.
- AI·캘린더·콘텐츠/인물·관리자는 기존 서비스 범위를 삭제하지 않지만 이번 3탭의 활성 기능으로 새로 추가하지 않는다. 운영 배포·리그·F14 이메일 알림 보류를 유지한다.

## 3. 목적지와 사용 흐름

| 목적지 | 사용자 목적·첫 내용 | 주요 연결 |
| --- | --- | --- |
| 포트폴리오 | 내 자산 요약, 조회 상태, 보유 자산/거래 내역 | 거래 기록·수정/삭제·보유 조정·평가·기간 수익률 |
| 이슈 | 발행된 경제 뉴스 목록 | 분류/페이지·상세·출처. 뉴스/통합 검색은 플랫폼 지원 여부 확인 후 노출 |
| 내 계정 | 로그인 상태와 내 정보 | 로그인·닉네임·로그아웃·탈퇴·피드백. 환율 조회의 보조 진입은 D01과 함께 검토 |
| 상단 검색 | 탭과 무관하게 종목을 찾음 | 검색 결과 → 종목 선택 → 최근 종가/기준일. 거래 원장 저장은 별도 명시적 동작 |

### 검색 초안 제안 — D01

첫 적용은 **F03 종목명/코드 검색**을 사용하고 표시 문구도 `종목 검색`으로 한정한다. 이는 현재 Android 구현을 재사용하는 제안이며 상단 검색의 최종 범위는 검토 대상이다. F09 뉴스·콘텐츠 통합 검색이 모든 플랫폼에서 동작한다고 표현하지 않는다.

1. 검색창 선택 시 종목 검색 본문을 연다. 기존 주 탭은 복귀 목적지로 유지한다.
2. 국내/미국과 주식/ETF 구분·검색 조건·결과·로딩/빈 결과/오류를 표시한다. 상세 검증·최대 개수는 F03을 따른다.
3. 결과 선택 시 종목명·코드·통화·최근 저장 종가·실제 기준일을 표시한다. 실시간 시세라고 부르지 않는다.
4. 선택 상태에서 새 검색어를 입력하면 이전 선택·가격 초안을 해제한다. 늦게 도착한 응답이 새 검색/수동 입력을 덮지 않는다.
5. 검색 복귀 시 시작한 탭으로 돌아간다. 검색어·필터 유지 범위와 프로세스 종료 복원 보장은 플랫폼별로 명시한다.

### 포트폴리오·거래 초안 제안

- 정상 본문 순서: 자산 요약 → 자산 분석 → 보유 자산/거래 내역 → 지원되는 관련 소식. 미구현 분석/소식을 채우기 위한 빈 큰 패널은 만들지 않는다.
- `거래 기록`을 선택하면 별도 입력 화면/시트를 연다. 초기 스크롤은 맨 위이며 제목·닫기·입력 label이 보인다.
- 종목 선택 → 매수/매도 → 거래 필드 입력 → 명시적 저장 → 결과 확인 → 내역 재조회 순서다. 입력값·날짜·불변 필드 규칙은 F05를 재사용한다.
- 삭제/보유 제거는 대상과 영향을 확인한 뒤 실행한다. 요청 중 중복 저장/삭제를 막는다.
- 저장 결과가 불명확하면 성공으로 표시하거나 자동 재전송하지 않는다. 내역 재조회로 확인하게 한다.
- 계산용 초안과 회원 원장을 구분한다. 비회원이라는 이유로 임시 저장 기능이 이미 있다고 안내하지 않는다.

### 복귀·초안 보존 — D02

목록 상세의 복귀는 목록 조건/페이지로 돌아가고, 거래 입력 닫기·시스템 뒤로 가기는 포트폴리오로 돌아간다. **거래 입력 중 상단 검색/다른 탭을 선택할 때의 초안 보존·이탈 확인은 미확정**이다. 이 초안에서는 조용히 버리거나 자동 저장하는 동작을 승인하지 않는다. 문서 확정 시 하나의 정책으로 명시하고 검증한다.

## 4. 화면 상태와 데이터의 정직한 표현

| 상태 | 표현·가능한 동작 | 금지/주의 |
| --- | --- | --- |
| 최초 조회 전·로딩 | 한 상태 안내, 필요시 진행 표시, 중복 요청 제어 | 빈 포트폴리오나 0원으로 확정하지 않음 |
| 정상·보유 있음 | 실제 서버 응답의 요약·단위·기준일·보유 목록 | 임의 수익률·그래프·합계를 생성하지 않음 |
| 정상·빈 보유 | 확인된 빈 상태와 첫 거래 CTA | 로그인 필요/장애와 구분. 0원은 확인된 빈 상태에만 사용 |
| 비회원·세션 만료 | 로그인 안내·실제 계정 화면 연결 | 이전 회원 데이터 제거. 지원하지 않는 게스트 저장을 약속하지 않음 |
| 조회 오류·서버 미연결 | 오류 문구와 사용자 재시도. 이전 값이 보이면 마지막 조회 자료임을 표시 | 오류를 빈 성공으로 바꾸지 않음. 반복 `—` 요약 노출 방식은 D03 |
| 가격/환율 없음·부분 평가 | `—`, 미평가 항목·이유와 PARTIAL/MIXED_DATES 구분 | 알 수 없는 합계/손익/수익률을 0이나 완성된 값으로 만들지 않음 |
| 저장 중 | 진행·중복 제출 차단, 입력/취소 가능 여부 명시 | 화면 이동만으로 서버 처리가 취소됐다고 가정하지 않음 |
| 저장 결과 불명 | 재전송 방지·내역 조회로 확인 | 무조건 성공 또는 자동 재시도 금지 |
| 미구현 | 숨기거나 명확한 준비 중 문구. 액션은 제공하지 않음 | 활성처럼 보이는 버튼·샘플 결과로 기능 완료를 암시하지 않음 |

금액 숨김은 숨길 범위와 접근성 이름을 명확히 하고, 화면에 마스킹한 금액을 스크린리더가 원문으로 읽지 않도록 한다. 뉴스/외부 출처는 안전한 링크로 제공한다. 인증/권한 실패의 판단 순서는 서비스 계약을 따른다.

## 5. 시각 기준과 플랫폼 관례

원본 웹의 흰 표면·검정 주요 동작·청색 보조 강조·얇은 구분선·숫자 중심 위계를 유지한다. 관찰된 토큰은 `surface #ffffff`, `text #171821`, `action #0a0a0a`, `primary #326bd5`, `border #e4e7ef`다. 원본의 모든 CSS 변수나 작은 글자를 그대로 채택하지 않는다.

아래는 **시안에서 확인할 제안**이다. 현재 APK 수치를 승인한 것으로 세지 않는다.

- 제목/본문/보조문에 분명한 크기 차이를 두고, 한국어·긴 종목명·큰 숫자를 줄여 숨기지 않는다. 본문은 16, 보조문은 14 수준을 출발점으로 플랫폼 글꼴 배율을 적용한다.
- 간격은 8/16/24 단위를 중심으로 묶음과 구분선을 사용한다. 카드 안에 카드를 쌓거나 무의미한 큰 빈 패널을 만들지 않는다.
- 아이콘은 텍스트를 대체하지 않는다. 필요 여부·한 계열·선택 상태·접근성 이름을 시안에서 정한다. 현재 텍스트 탭을 최종 아이콘 디자인으로 확정하지 않는다.
- 일반 본문 대비 4.5:1, 큰 글자 3:1을 검토 기준으로 삼고 색 외 부호/문구로 손익·오류를 전달한다.

| 대상 | 플랫폼별 적용·확인 |
| --- | --- |
| Android | 최소 48dp 터치, 시스템 뒤로 가기·IME·TalkBack·글자 배율·회전 |
| iOS | 기본 뒤로 가기/시트·최소 44pt 터치·Dynamic Type·VoiceOver |
| React Native | 실행 OS의 입력/접근성·safe area·뒤로 가기·글자 배율 |
| Flutter | Semantics·SafeArea·포커스/키보드·화면 재생성·텍스트 배율 |
| WebView | DOM 의미 역할·키보드 포커스·호스트 뒤로 가기·화면 확대. 호스트와 웹 바를 중복하지 않음 |

접근성 수치는 검토 기준이며 기기/발화 검증 완료가 아니다. 좁은 화면·가로·글자 200%·키보드에서 검색창/본문/하단 바가 겹치지 않아야 한다. 다크 테마는 토큰·대비 검토 없이 자동 지원으로 표시하지 않는다.

## 6. 명세 확인 → 이미지 시안 → 실제 구현

1. 이 초안의 D01–D04와 대표 상태를 확인한다. 기존 기능 계약을 재작성하지 않는다.
2. `imagegen-frontend-mobile`로 대표 Android 화면 **한 장**을 생성한다. 확정한 탐색·원본 토큰·구현 경계를 입력하고, 시각 검토에 필요한 데이터는 샘플임을 표시한다. 승인된 대표 이미지와 이후 적용 결과는 아래 진행 상태에 연결한다.
3. `ui-ux-pro-max`로 정보 위계·입력·탐색·접근성을 점검한다. 스킬을 읽었다는 사실을 검증 통과로 세지 않는다.
4. 명세와 시각 기준을 확인한 뒤 구현에 착수한다. 이미지를 앱 화면에 붙이는 방식으로 대체하지 않는다.
5. 구현 후 실제 앱을 같은 상태에서 시안과 대조한다. 구현 역할과 검증 역할을 구분하고, 바뀐 범위의 기존 검사와 필요한 새 인수 검사를 사용한다.

새 hook/하네스/A/B/모델 비교·다섯 앱 동시 구현은 이번 명세 작업 범위가 아니다. 기존 agent 역할 JSON·hook 설정은 실행 증거와 구분한다.

확정된 상단 검색·하단 3탭 자체는 다시 선택할 항목이 아니다. 미결정 제안은 이번 문서만으로 제품 동작으로 승격하지 않는다.

## 8. 완료·검증 기준

이번 문서 작업의 완료: 기존 계약 출처·확정/제안/미결정 구분·주요 흐름/상태·플랫폼 차이·다음 이미지 단계의 입력·문서 링크를 확인한다. **앱 수정·이미지 생성·빌드·DB·기기 실행을 하지 않는다.**

후속 구현 인수 항목: 검색과 3탭의 실제 연결/고정 위치, 조회 전·401·오류·빈 보유·부분 평가, 늦은 응답/새 검색/수동 단가, 거래 입력/닫기/뒤로 가기/초안, 결과 불명과 중복 전송 방지, 큰 글자/가로/키보드/스크린리더. 대상 플랫폼에서 실제 수행한 범위만 완료로 기록한다.

시간·토큰·실패·재독·미검증은 [기존 실험 4](../docs/time-token-experiment.md)에 단계별로 이어 기록한다. 시안/구현/문서 작업을 같은 조건의 비용 비교로 취급하지 않는다.

## 9. 승인 시안 적용 상태 — Issue #15 · PR #19

2026-11-04 사용자가 대표 포트폴리오 시안을 승인하고 Android Compose 구현을 요청했다. [승인 이미지](../docs/design/2026-11-04-web-reference/concepts/portfolio-v1.png)와 [Android 적용 계약](android-native/portfolio-design.md)을 따른다. 상단 검색/하단 3탭은 실제 탐색에 연결했고, 첫 로딩·로그인 필요·조회 오류에는 미확인 요약을 숨긴다. 평가 전·부분 평가·실제 빈 보유를 구분한다. 거래 초안/금액 숨김 상태를 탭별로 보존한다. 이 기록은 앞선 명세 작성 단계의 실행 금지를 구현 승인 이후로 확장하지 않으며, 다른 플랫폼 구현 완료를 뜻하지 않는다.

## 10. 이슈·내 계정 공통 디자인 확장

포트폴리오만 시각 기준을 적용한 상태에서 멈추지 않고, 사용자 후속 요청에 따라 이슈와 내 계정도 같은 흰 표면·검정 주요 동작·청색 선택·20dp 모바일 여백으로 맞춘다. 별도 시각 방향이나 이미지 생성 없이 승인 토큰을 재사용한다.

- 이슈: 제목 중심의 평면 기사 목록과 구분선, 전체/오늘 모드의 청색 선택 표시, 분야 필터, 기존 페이지/상세/출처/뒤로 이동을 유지한다. 기사 이미지·키워드·AI 분석을 새로 구현한 것처럼 표시하지 않는다.
- 내 계정: 프로필/닉네임·서비스(환율/의견)·계정 관리(로그아웃/탈퇴)로 구분한다. 확인되지 않은 프로필·회원 혜택·설정 메뉴를 만들지 않는다. 조회 중·401·503을 구분하고 503은 재조회, 401은 로그인으로 복구한다. 로그인 시작/취소·실패 뒤 재시도를 막지 않는다.
- 포트폴리오: 정상 화면의 독립적인 새로고침 버튼을 제거한다. 화면 재진입 조회와 실제 평가/기간 조회는 유지하며 조회 실패의 다시 조회는 복구 동작으로 남긴다. 자동 폴링을 추가하지 않는다.

이는 기존 기능의 디자인/상태 표시 확장이다. 서버/API·오늘 뉴스 날짜 정책·미구현 기능의 범위를 바꾸지 않는다. 실행/접근성 검증의 한계와 시간·토큰은 실험 4에 이어 기록한다.
