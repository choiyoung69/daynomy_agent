# Android 다음 묶음 — 역할 3개 분리와 KB 우선

상태: 실제 검사·별도 검증 승인·최종 소스 대조 완료. 이번 묶음은 공개 뉴스 목록·상세와 USD/KRW 환율 조회다.
전체 앱 완료와 구분하며 앞선 종목 검색·종가 파일럿은 runs/014에 보존한다.

## 배정과 입력

사용자 요청에 따라 테스트 작성(android_next_tests, gpt-6-astra/high),
구현(android_next_implementation, gpt-6.1-sol/medium),
검증(android_next_validation, gpt-6-astra/high)을 서로 다른 서브에이전트로 분리했다.
root는 계약 고정, KB 입력, 공유 실행 환경과 기존 앱의 탐색 연결을 담당한다.
테스트 작성자가 자신의 테스트 기대값을 승인하는 구조가 아니다.
설정은 agents/android-native.json에 있고 에이전트 배정은 대화의 root가 수행한다.

각 역할은 로컬 KB를 먼저 읽고 필요한 원본만 보완했다. 전체 문서를 매번 넣지 않고
환율·뉴스·화면별5문서 패킷을 experiments/android-native/next/knowledge에 고정했다.
해당 묶음에 준비된 기존 Android 도구 버전을 재사용하며 앱 전체의 준비 완료로 확대하지 않는다.
외부 웹 조회는 수행하지 않았다. 기능 계약 본문이 비어 있는 KB 부분은 원본 분석이 필요했고
명세 spec/android-native/discovery.md에 실제 요청·응답 규칙과 의도적 차이를 고정했다.

## 실제 파이프라인

환율 client 테스트 → 별도 검증자의 stub red → 환율 구현 중 뉴스 테스트 작성 →
환율 controller red/구현 → 뉴스 client red/구현 → 뉴스 controller red/구현 →
코어·Rust/DB 검사 중 네이티브 화면 구현 순서로 독립 작업을 겹쳤다.
각 기능의 테스트 작성은 해당 구현보다 먼저 진행했고 고정 SHA를 검증자와 구현자에게 전달했다.
기기 테스트는 구현 전에 작성했지만 기기에서 red로 실행했다고 주장하지 않는다.
검증 에이전트가 테스트 기대값과 원본을 독립 대조하면서 환율 underflow 누락을 발견했고
테스트 작성자에게 별도 경계1개를 보강하도록 돌려보냈다. 기존 고정 기준을 약화하지 않았다.

독립 역할의 실제 실행/실패/파일 해시/KB 적용은 experiments/android-native/next에 기록한다.
정확한 요청 시작 시각은 미측정이며 최초 에이전트 보고 시작은2026-10-28 09:09:39 UTC다.
root 시작을 과거 오프셋으로 추정하지 않는다. 에이전트 수만으로 배속을 주장하지 않는다.

## 기존 환경 재사용

기존 Gradle wrapper·잠금 의존성·HTTP 전송·모델·상태 도구를 사용한다.
android_backend_fixture.py에 opt-in --discovery 합성 seed만 더했다.
원본·Rust 기능 코드·실제 사용자 데이터는 수정하지 않는다. 공유 DB 잠금과 전용 에뮬레이터를 사용한다.
Gradle 검사는 검증 역할의 독점 슬롯에서 실행하며 다른 역할이 동시에 실행하지 않는다.

## 계약 경계

뉴스 응답은 원본 웹의10분류를 해석하지만 조회 필터는 서버가 지원하는 전체/부동산/주식/ETF만 노출한다.
상세 본문 문자열의 빈 줄 제거와 배열 허용은 원본 웹 동작을 따른다.
목록 nullable 필드의 누락과 상세 optional 필드의 null은 별도로 구분한다.
뉴스 ID는 signed Long의 정확한 범위이며 stock의 safe positive ID 계약을 복사하지 않는다.
환율은 원본 웹의 baseDate+finite positive rate 투영을 따르며 숫자 원문은 BigDecimal로 보존한다.
예외 본문을 UI에 노출하지 않고 실패·빈 성공·취소·재시도를 구분한다.
뉴스 이미지/키워드/시장 분석/오늘 뉴스 전체 이식, 로그인·포트폴리오·운영 배포는 이번 묶음 밖이다.

## 완료 결과

최종 승인은 [validation-final.json](../experiments/android-native/next/validation-final.json),
root의 실제 XML/소스/고정 기준 재확인과 정리는 [result.json](../experiments/android-native/next/result.json)에 있다.
첫 에이전트 보고 시작09:09:39 UTC부터 독립 최종 승인09:34:12 UTC까지 약24분34초다.
정확한 사용자 요청 시작부터의 총 시간·전체 앱 개발 시간·순차 대비 배속은 아니다.
테스트 작성 중 환율/뉴스 구현을 넘겨 진행한 실제 구간은 tests.json과 implementation.json에 구분했다.

코어 실제88개 JVM·10개 Rust/DB 검사는 통과했다. 신규분은36개 JVM·3개 실제 HTTP/DB이며
나머지는 기존 회귀다. 결과는 verification-core.json에 코드·기준·XML 해시와 함께 있다.
3차 실제 기기8/8, APK/기기 테스트 APK 빌드와 Lint가 종료0으로 성공했다.
신규3개·기존5개 모두 통과했다. 아래 실패를 성공으로 덮어쓰지 않는다.
검증자는 동일 검증 APK를 실제 Rust 서버에 연결해 뉴스 목록·상세 문단·출처와 환율 소수/실제 기준일도
직접 확인하고 화면/접근성 XML을 보존했다. 이 관찰을 기기 테스트8개에 추가 합산하지 않는다.
root는39개 현재 검토 소스와7개 고정 테스트 해시·실제 XML88/10/8을 다시 대조했다.
검사 뒤 자기 서버·합성 DB·전용 에뮬레이터를 종료했고 기존 사용자 DB 서비스는 중단하지 않았다.

## 실패·수정 이력

- 최초 red 실행의 sandbox 데몬 소켓 오류는 환경 실패로 별도 보존했고 red 통과로 세지 않았다.
  이후 실제 컴파일·실행한 환율 client9/controller7, 뉴스 client14/controller5의 미구현 실패만 고정했다.
- 1차 앱 검사: APK 빌드 성공, 실제 기기8개 중 신규3개 성공·기존5개 실패.
  종목 클릭 후 단가 화면 timeout4개와 ETF 카드 가시성1개였다. 공통 탭 추가 후 검색 화면의
  공간이 줄어든 회귀로 보고 구현 역할에 기존 화면의 중복 제목/설명 제거·패딩 축소를 배정했다.
  단언·기준은 변경하지 않았다. 1차 검사는 최종 Lint에 도달하지 않아 Lint 성공으로 세지 않는다.
- 2차 앱 검사: 기존5개는 모두 성공, 전체7/8 성공. 환율 오류 노드는 존재했지만 즉시 가시성
  단언이 실패했다. 검증자 로그에서 IME 표시와 빠른503 응답이 겹쳤다. 지속적 가림인지
  일시적 IME 전환 경쟁인지는 해당 결과만으로 확정하지 않는다.
- 테스트 작성자는 표시 단언이 사용자 요구에 맞다고 독립 재확인했다. 노드 존재 대기는
  가시성을 보장하지 않지만 기준을 약화하지 않았다. 구현자가 환율 조회 때 입력 focus를
  해제하고 배치를 줄인3차 수정본을 같은 원래 기준으로 검사해8/8 성공했다. Lint도 완료했다.

실패별 XML·로그·당시 소스/APK 해시는 validation-app-attempt-01/02.json에 보존한다.
첫 회귀 수정과 별도의 환율 가시성 수정은 서로 다른 원인에 대한 수정이다.

## 구현 범위의 한계

테스트42개를 새로 추가했고 기존64개와 함께106개가 통과했다(88 JVM+10 HTTP/DB+8 기기).
이 수치는 앱 전체 기능 수나 모든 장애 상황의 무결함을 의미하지 않는다.
뉴스 원본 웹은 응답 Content-Type도 검사하지만 이번 공통 전송 인터페이스는 성공 본문만
노출하므로 뉴스의 JSON/필드 검증과 MIME 헤더 완전 동치를 주장하지 않는다.
원격 이미지 렌더링, 다른 OS/실기기·프로세스 종료 복구·TalkBack 전체 인수,
로그인·거래·AI·나머지 앱 기능과 운영 release 주소 구성이 남았다.
고정 테스트는 기존 조건을 유지했으며2번의 UI 수정으로 가시성 회귀를 해결했다.
