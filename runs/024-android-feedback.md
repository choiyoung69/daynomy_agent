# Android F11 피드백 구현 기록

기준: main에 병합된 작업 흐름 개선 PR #8. 기능 이슈: #9. 기존 Android 앱에 F11을 추가했다. 새 실험·하네스·모델 비교는 만들지 않았다.

## 동작과 범위

- 계정 → 의견 보내기. 비로그인 입력, 원문 UTF-16 길이·Java 공백 검증, 기존 CSRF 쿠키/헤더로 POST, 빈 204 처리.
- 전송 중 수정·중복 클릭 차단. HTTP 오류는 초안 보존·수동 재시도, 응답 유실은 결과 불명·재전송 차단·새 의견 작성으로 초기화.
- ViewModel 수명으로 작업 보존, 종료 시 취소 및 늦은 결과 무시. 관리자 기능·서버 수정·배포는 제외.

## 필요한 지식과 검사

- 기존 ensure 시작: 기능/인증/JSON/취소 4문서만 선택. 수용 verify에서 고정 해시·출처·적용 매핑을 재확인한다.
- 원본 DTO의 길이 검사 순서와 Java 공백 조건을 계약으로 고정했다. 문자열을 미리 trim하지 않는다.
- 독립 테스트 작성 → 실제 RED(14개 중 13개 실패, 1개 취소 전파는 스텁에서도 통과) → 테스트 SHA-256 고정 → 구현 → 관련 GREEN.
- 고정 FeedbackContractTest 14개, 기존 Android30SessionContractTest 7개 통과. 실제 Gradle RED 8초, GREEN+APK 11초.
- 테스트 고정 해시: 09b33e00daeb680fbfeab7b21b0a6c87915209cc5a96c153aec1fc14aa428423
- 독립 읽기 전용 리뷰: 계약 위반 발견 없음. 독립 기기 검증이나 실제 DB 검증을 대신하지 않는다.
- 첫 기기 검사는 전송·성공 표시 후 초기화 단언에서 실패했다. 입력 노드가 라벨/글자수 안내까지 병합한다는 테스트 해석 오류로, 실제 EditableText는 빈 값이었다. EditableText만 비교하도록 UI 테스트를 수정하고 동일 1개를 재실행했다. 고정 JVM 계약 테스트는 수정하지 않았다.
- 기기 재검사: 기존 API33 ARM64 AVD에서 FeedbackScreenTest 1개 통과(0 skip/0 fail), Gradle 32초. 비로그인 계정 진입 → 입력 → 전송 중 버튼 비활성 → CSRF POST 1회 → 성공 → 새 의견 빈 입력 → 닫기까지 실제 Compose/loopback HTTP로 확인했다.
- 실제 Rust/DB 저장·실제 Google 인증·release 배포·프로세스 종료 후 초안 복원은 미검증.

## 남은 낭비와 다음 적용

- 빌드 자체보다 계약 정리·테스트/리뷰 전달·GitHub 기록·도구 왕복이 전체 경과의 대부분이다. 단계별 정밀 타이머는 없어 이를 수치 분해하거나 검증 대기를 전부 낭비로 단정하지 않는다.
- 4문서 선택은 전달 범위 축소의 증거이며 과거의 다른 기능과 직접적인 비용 절감률 비교는 아니다.
- 장기 대화의 조정 에이전트와 역할별 호출에도 공통 지시 문맥이 들어간다. KB만 줄여 전체 사용량이 작아졌다고 주장하지 않는다.
- 같은 기능의 다음 수정은 기존 패킷 재사용, 관련 테스트만 실행, 상태 확인은 완료 출력으로 묶는다. 독립 검증 기준은 유지한다.
- UI는 기존 Material 테마를 유지했다. UI/UX Pro Max의 제한된 검색에서 일치 항목이 없어 라벨·텍스트 상태·48dp·키보드 스크롤 기본 기준을 적용했다.
