# 009 — 빈 슬롯 자동 배정 실험

2026-10-21. 관리자 피드백 목록·상세 두 API를 새 후보에서 재작성했다.
기존 앱·원본에 자동 반영하거나 전체 서비스 구현을 시작한 실험은 아니다.

**판정: 동적 배정과 제한된 자동 수정은 확인. 최종 기능 승인은 거절됨.**

## 구성

```text
준비된 작업 큐 → AI 작업 슬롯 최대 3개
  구현 목록 / 테스트 목록 / 구현 상세 / 테스트 상세
                      ↓ 모두 완료
              실제 검사 슬롯 1개
                      ↓ 통과
              목록 리뷰 / 상세 리뷰
                      ↓ revise
          구현 수정 → 재검사 → 새 리뷰 (횟수·시간 제한)
```

- 구현·테스트 작성: gpt-6.1-sol, medium. 리뷰: gpt-6-astra, high.
- 역할 실행마다 새 CLI 세션이다. 6개 역할을 동시에 상주시킨 구조가 아니다.
  수정·재리뷰 때 세션이 추가된다. 이번 3개 상한은 실행기 설정이며 CLI의 전역 한도가 아니다.
- `scripts/task_queue.py`: 준비 작업 배정, 의존 관계, 실제 콜백 시작/종료·대기 시간,
  실패 전파와 마감 관리. 체크 프로그램은 AI 수에 포함하지 않는다.
- `scripts/admin_feedback_queue.py`: 역할별 쓰기 폴더, 모델 호출, 고정 테스트 가져오기,
  빌드·검사·리뷰·제한된 수정 연결. `--max-repairs`는 0~2이며 실행별 총 시간에서 차감한다.
- `scripts/admin_feedback_gate.py`: 전용 PostgreSQL과 실제 Spring/Rust 비교,
  전체 public 테이블 변경 여부, 소스·테스트·바이너리·기준 해시 확인과 정리.
- 모델 역할의 쓰기 권한과 리뷰 읽기 전용 권한은 CLI sandbox로 제한한다.
  전체 파일 읽기까지 적대적으로 격리한 것은 아니다.

## 시간 비교 — 구현·테스트 작성 4개 작업만

| 실행 | 준비 완료 | 최고 동시 작업 | 이후 판정 |
| --- | ---: | ---: | --- |
| 1슬롯 | 204.318초, 약 3분 24초 | 1 | Clippy 실패 |
| 3슬롯 | 115.374초, 약 1분 55초 | 3 | 컴파일 실패 |

이번 한 쌍에서는 준비 시간이 **43.53% 감소**했다. 모두 후속 검사에서 실패했으므로
검증 완료까지의 시간이나 전체 서비스 속도 개선 수치가 아니다. 모델 출력·응답 시간과
캐시·실행 순서가 달라 반복 측정이 필요하다.

상세 구현이 40.632초에 끝나자 같은 슬롯에서 상세 테스트 작성이 바로 시작됐다.
그때 다른 두 작업은 계속 실행 중이었다. 수동으로 다음 담당을 호출하지 않았다.
측정치는 모델 내부 연산 시간이 아닌 실제 작업 콜백의 구간이다.

로컬 증거:

- `.local/task-queue/preparation-comparison.json`
- `.local/task-queue/20261021T053956Z/slots-1/queue/state.json`
- `.local/task-queue/20261021T054424Z/slots-3/queue/state.json`

## 발견 → 수정 → 재검증

1. 기본 PATH의 CLI 0.149.1은 지정 모델을 거절했다. 6.115초 후 후속 호출을 중단했다.
   이미 설치된 앱 번들 CLI 0.162.0-alpha.17.2를 명시하자 같은 모델 호출이 성공했다.
   모델·전역 설정·설치를 바꾸지 않았다. 공식 모델 접근 조건은 [모델 안내](https://learn.chatgpt.com/docs/models)를 참고한다.
2. 1슬롯 후보는 13개 함수 테스트를 통과했지만 Clippy가 거절했다.
   3슬롯 후보는 `json!` 안의 인덱싱 표현식 때문에 컴파일이 실패했다.
3. 별도 복구 실행에서 구현 담당이 컴파일 오류를 고쳤다. 고정된 함수 테스트 12개와
   Clippy는 통과했지만 실제 Spring 비교 18개 중 6개가 실패했다.
   오류 문구와 생략해야 하는 `errors` 필드가 달랐다.
4. 최초 원본 발췌에 공통 오류 코드·응답 정의가 빠져 있었다. 이 3개 파일의 추가 전송은
   자동 승인 검토가 차단했고, 사용자 추가 동의 후 실행했다.
5. 다음 실행은 두 구현 수정 → 함수 테스트 12개 → Clippy → Spring/Rust 18/18 → 리뷰를
   자동 연결했다. 리뷰가 숫자 바인딩 차이와 불충분한 테스트를 지적해 다시 수정 요청했다.
   같은 실행기가 두 구현 수정·재검사·새 리뷰를 자동 실행했다.
6. 마지막 검사도 12개 함수 테스트·Clippy·18개 원본 비교를 통과했지만,
   최종 리뷰 둘 다 `revise`였다. 숫자 변환의 추가 경계값과 오류 JSON 전체 비교 등
   테스트 보강이 필요하다. 리뷰의 추가 경계값 주장은 아직 모두 실제 Spring 요청으로
   확인한 사실이 아니다. 전체 호환 완료로 세지 않는다.

마지막 두 단계 자동 실행은 합계 **326.399초, 약 5분 26초**였으며 최종 상태는 failed다.
별도 앞선 복구는 47.192초다. 이 시간은 실행기 작성·중간 분석·승인 대기를 포함하지 않는다.
원래 1슬롯/3슬롯 기록과 복구 기록을 합쳐 공정한 완료 시간 비교라고 부르지 않는다.

- 첫 복구: `.local/task-queue/20261021T054854Z/slots-3/`
- 후속 자동 실행: `.local/task-queue/20261021T055224Z/comparison.json`
- 최종 검사·리뷰: `.local/task-queue/20261021T055224Z/slots-3-repair-1/`
- 모든 복구에서 최초 3슬롯 함수 테스트 두 파일의 바이트가 유지됐다.
  실제 HTTP 기대값 해시도 세 비교 실행에서 동일했다.
- 실제 원본/실행 복사본 474개 해시 확인. 전용 DB 삭제·서버 종료 성공.
  종료 후 PostgreSQL이 실행 중이지 않음을 확인했다.

## 실행기 자체 검증과 남은 일

독립 테스트 작성·검토를 통해 다음 실행기 오류도 수정했다.

- 제출된 작업 수를 실제 동시 실행 수로 잘못 세던 측정, 이벤트 시각 역전.
- 공유 검사 잠금의 무기한 대기.
- 복구 도중 컴파일 실패하면 다음 재시도에서 초기 작업 ID를 찾다 중단되는 문제.
- 복구 단계 간 고정 HTTP 기준 해시 연결 누락.
- 이전 리뷰 지적을 새 리뷰에 전달하지 않아 미해결 테스트 요청이 잊힐 위험.

마지막 문제는 새 코드에서 `pending-test-revisions.json`을 보존하고,
테스트 보강 요청이 남으면 새 리뷰 호출 전에 `needs_test_revision`으로 중단하도록 막았다.
구현만 고쳐서 테스트 보강까지 해결됐다고 판정하지 않는다. 이 마지막 보호 장치는
회귀 테스트로 확인했으며, 이미 실행 중이던 위 모델 실험 전체를 다시 돌린 결과는 아니다.

**다음 작업은 리뷰가 지적한 테스트 보강을 별도 테스트 작성 역할에 배정하는 연결이다.**
현재 자동 복구는 구현 파일만 고친다. 테스트를 임의로 바꿔 통과시키지 않는다.
이번 실행기의 수정·원본 발췌 보완·별도 복구 시작에는 이 대화의 Codex가 개입했다.
전체 준비 과정까지 무인으로 해결됐다는 뜻은 아니다.

마지막 실행기 회귀 검사는 **80개 통과**했다. 큐 15개, CLI 조정기 42개,
관리자 샘플 조정기·잠금 23개다. Python 구문 검사와 `git diff --check`도 통과했다.
이 80개와 실제 Rust 함수 테스트·HTTP 비교·모델 리뷰 결과를 합산하지 않는다.

마감 시 실행 중인 임의 Python 콜백을 큐가 강제 종료하지는 못한다.
CLI 실행기는 자체 마감과 프로세스 그룹 정리를 담당한다.

재실행 예시(실제 외부 모델 호출·전용 로컬 DB 사용):

```sh
python3 scripts/admin_feedback_queue.py --slots 3 --timeout 360 \
  --codex /Applications/ChatGPT.app/Contents/Resources/codex-cli/CodexCLI.app/Contents/MacOS/codex
```

기존 미커밋 작업을 보존했고, 이번 변경은 커밋하지 않았다.
