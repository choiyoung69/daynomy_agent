### 다음에 진행할 작업

1. **원본과 달라진 정책을 확정한다.** 로그인 보안 강화, AI 실패 시 공유 캐시 갱신 범위,
   최대 페이지에서 원본이 500을 반환하는 사례 등을 아래 한계와 함께 검토한다.
2. **실제 제공자의 개발 환경으로 연결을 확인한다.** Google 로그인·토큰 갱신, AI 응답,
   S3 업로드·삭제, 시세·환율·뉴스·공시 수집을 각각 확인한다.
3. **연결된 사용자 흐름을 재검증한다.** 로그인 → 거래 등록 → 보유자산·수익률 조회 →
   AI 분석 → 가격 수집 후 성과 갱신을 실제 제공자 환경에서도 확인한다.
4. **배포까지 진행할 경우 운영 준비를 별도로 한다.** DB 연결·마이그레이션·예약 작업의
   재시작 처리·실패 복구를 운영 환경에서 확인한 뒤 배포 완료를 판단한다.

리그·UI·F14 이메일 알림은 합의해서 제외한 범위다. 위 남은 검증과 구분한다.
전체 서비스를 무인 실행기로 개발하려면 기능별 작업 배정·의존 관계·통합 기준을
샘플 실행기보다 넓게 연결하는 별도 작업도 필요하다.

상세 실행 증거는 아래 `.local/` 경로에 있다. `.local/`은 Git에서 제외되므로
다른 PC로 코드만 옮기면 해당 증거가 함께 전달되지는 않는다. 그 환경에서는 실행 안내에 따라 재검증한다.

Rust HTTP/DB 사례 합계는 567개다. 서로 다른 suite에 같은 경로가 반복될 수 있으며,

### 의도적으로 틀린 후보 검사

실제 소스는 그대로 두고 격리한 복사본에만 세 결함을 넣었다.
각 후보는 검사에 실패했으며 부모 집계는 이를 결함 탐지로 판정했다.

| 주입한 결함 | 실제 검사에서 발견한 결과 |

리그 테이블은 원본 스키마 호환성을 위해 남지만 리그 기능은 제공하지 않는다.

## 검사가 실제로 찾아낸 문제

- DB 숫자를 검사기가 float로 읽는 문제와 잘못된 SQL fixture 구분자를 수정했다.
  응답·정확한 금액 비교 기준은 유지했다.
- 본문 없는 POST를 JSON이 아니라는 이유로 415 처리하던 서버 분기를 수정했다.
- 분석 재사용 시 lease 갱신이 DB 수정 시각을 바꾸던 문제를 수정했다.
- 공개 입력의 최대 50종목/15자리 가격 제한을 저장 포트폴리오에도 적용하던 문제를 분리했다.
- 국내 가격 수집 후 포트폴리오 과거 성과를 갱신하는 연결을 추가했다.
  스냅샷 실패가 이미 커밋한 가격을 취소하지 않는 회귀 검사도 통과했다.
- 한글 YouTube 핸들을 이중 URL 인코딩하던 문제를 수정했다.
- AI 근거 날짜·보정 요청·V1 캐시 분리·배치 실패 전파는 심화 리뷰에서 추가로 찾아 수정했다.
  독립 HTTP 검사 54개와 다시 대조했다. 느린 첫 요청과 빠른 둘째 요청이 있을 때
  셋째 요청이 빈 슬롯에서 즉시 시작하는 사례도 포함한다.

## 하네스 재실행 기록

이 절의 대상은 `experiments/admin-feedback/` 목록·상세 샘플이다. 전체 백엔드의
567개 검사와 별도로 실행했으며 성공 후보는 격리된 실행 폴더에 보관한다.

과거 고정 테스트를 보존하면서 테스트 보강 지적을 별도 작성 역할에 다시 배정하는 연결을 추가했다.
첫 실제 재실행은 557초 후 실패했다. 두 번째 테스트 작성이 원본과 다르게 `+0x1`을
허용한다고 가정했고, 검사가 이를 발견해 완료를 막았다. 이 실행을 성공으로 바꾸지 않았다.

새 v2는 모델을 배정하기 전에 원본 응답 106개를 관측하고 근거를 고정한다.
원본의 `page=2147483647`이 정확한 일반화 500을 반환하는 것도 기록했다.
다른 예상하지 못한 500을 허용하는 방식은 아니다.
첫 v2 원본 검사는 이 경계 사례 때문에 모델 배정 전에 중단됐다.
그 뒤 원본 106개 사전 검사는 통과했지만 첫 구현 모델이 개별 150초 제한에 걸렸다.
호출 실패 이후 다른 모델 요청을 반복하지 않고 중단했다. 근거 요약 후 240초로 한 차례
재검증했지만 파일 작성 도구 호출 중 다시 시간 초과했다(총 254.800초). 미완성 후보는 가져오지 않았다.

그 뒤 `--artifact-mode response`를 추가했다. 구현·테스트 역할은 완전한 Rust 소스를
엄격한 JSON으로 반환하고, 하네스가 검증 후 지정된 파일에만 저장한다. 모델은 파일을
직접 수정하지 않는다. 원본 106개·기존 고정 검사·red/green·별도 리뷰는 유지한다.
첫 응답 방식 실행은 1개 슬롯에서 자동 수정 포함 500.301초 후 실패했다.
구현·테스트 작성 4회가 끝났고, 함수 테스트와 자동 Clippy 수정도 동작했다.
실제 원본 비교는 106개 중 98개 통과, 8개 실패로 리뷰 진입을 막았다.
실험용 HTTP 서버가 URL 인코딩을 풀지 않고 detail 함수에 전달하는 경계 연결 오류였다.
이전 실패 기록은 그대로 두고 어댑터·역할 입력 계약을 고쳤다. 한 번만 디코딩하고
문자 `+`를 보존하는 어댑터 검사 3개를 추가했다.
3개 슬롯의 새 실행은 자동 수정·별도 리뷰까지 **373.134초(약 6분 13초)에 completed**로 끝났다.
첫 검사에서 나온 Clippy 오류를 하네스가 목록·상세 구현 역할에 자동 재배정했다.
독립 테스트는 고정한 채 수정한 뒤, red/green·빌드·엄격한 Clippy·원본 비교 106개를
통과했고 `gpt-6-astra high` 리뷰 2개가 각각 승인했다. 검토자는 읽기 전용으로
기존 테스트 바이너리도 다시 실행했다. 실제 최고 동시 모델 호출 수는 3이다.

| 단계 | 실제 경과 시간 |
| --- | --- |
| 원본 관측·준비 | 약 13.5초 |
| 구현·테스트 작성 4개, 최대 3개 병렬 | 135.7초 |

가장 오래 걸린 작업은 목록 첫 구현 135.7초와 목록 수정 104.3초였다.
실제 검사 두 번은 합쳐 약 57초다. 이 샘플에서는 모델의 코드 작성·수정 응답이
주요 병목이었으며, 준비된 독립 작업이 없을 때까지 3개 슬롯을 강제로 채우지는 않았다.
1개 슬롯 실행의 첫 작성 4개는 334.3초였다. 두 실행의 경계 계약·생성 코드가 달라
엄밀한 성능 A/B 비교로 보지는 않는다.

실행 경로: `.local/task-queue/20261021T071930Z-response-parallel/`.
첫 실패 단계와 성공한 `slots-3-repair-1`을 모두 보존했다.
집계는 `.local/three-hour-service/20261021T060305Z/final-harness-replay.json`에 있다.

반복된 Clippy 사례는 이후 배정용 계약에 예방 문구로 추가했다. 실제 이번 실행은
기존 문구로 시작했으며, 해당 오류는 자동 검사·수정 단계가 해결했다.
테스트 보강 재배정 연결의 과거 실패 기록도 유지하며, 이번 성공 실행에서는
추가 TEST_REVISION 요청이 나오지 않았다.

검사 반복으로 생긴 약 20GB의 Cargo 중간 산출물은 정리했다. 소스·고정 기준·보고서와
검사한 실행 파일은 해시를 확인하며 보존했고, 현재 서비스 실행 기록은 약 730MB다.

## 한계·판단 보류

- 제공자 검사는 로컬 모의 서버·합성 데이터다. 실제 Google 계정, 유료 AI, IAM/S3,
  공공데이터의 현재 서비스 응답과 운영 배포는 검증하지 않았다.
- 뉴스·인물 삭제에서 외부 S3 삭제 후 DB 커밋 실패 시 객체를 복원하지 못하는 위험은
  원본에도 있다. 업데이트의 새 객체 보상 삭제와 구분한다.
- 스케줄러는 명시적 활성화와 작업 목록이 있어야 실행한다. 재시작을 넘는 배정 체크포인트는
  저장하지 않는다. cron의 L/W/# 확장 문법은 지원하지 않고 거절한다.
- DART/기관 HTML 파서는 제한된 구조를 다룬다. 모든 실제 HTML 변형과 중첩 표의 동치성은 미검증이다.
- OIDC의 PKCE S256·미인증 이메일 거절은 강화된 목표다. 원본과 바이트 단위로 같은
  로그인 정책이라고 주장하지 않는다. 실제 Google 통합과 함께 정책 확인이 남는다.
- AI 배치의 공유 캐시는 모든 제공자 배치가 성공한 뒤 갱신한다. 실패한 요청에서 일부
  성공 배치의 캐시를 남기는 원본과 보수적인 차이가 있다.
- 서울 자정 경계를 가상 시계로 재현한 검사는 아직 없다.
- 샘플의 원본 106개 재현은 전체 `app/`의 모든 경계 동작이 같다는 보장이 아니다.
  최대 페이지에서 원본이 500을 반환하는 등의 이상 동작은 운영 정책 확인 대상으로 남긴다.
- 이번 요청에는 커밋·배포를 포함하지 않았다.

구현·검증 종료 후 사용자가 변경을 매우 작은 커밋 단위로 저장하도록 요청했다.
기존 `ab4cac0` 이후 변경을 **65개 로컬 커밋**으로 나누었다. 기존 커밋 이력은 유지했다.

- Rust 기능 모듈과 기능별 검증기, 실행 기록·안내 문서를 각각 분리했다.
