# 022 — 기존 로그의 시간·토큰 병목과 패키지 구조 개선 보고서

- 분석일: 2026-11-04, Asia/Seoul.
- 관련 Issue: [#3](https://github.com/choiyoung69/daynomy_agent/issues/3).
- 코드 기준: `f6519129200af8bba00859b2337560613da18698`. PR #2 머지 후 main의 정적 열람 기준이다.
- 분석 범위: 2026-10-26~11-01 KST 필터의 daynomy_agent 요청 81개·모델 응답 4,094개. 보존된 해당 사용량은 10월 27~28일에 발생했다.
- 이번 변경: 보고서·수치 요약·구조 안내. 앱·하네스·KB 선택 로직은 수정하지 않았고 모델/서버/DB/빌드/테스트를 재실행하지 않았다.

## 결론

우선 개선할 병목은 ① 공유 검증 환경의 긴 잠금과 준비 실패, ② 검증·상태 확인의 잦은 왕복, ③ 긴 공통 문서의 역할별 재탐색과 넓은 지식 전달이다.
큰 사용량 작업의 전체 토큰을 낭비로 분류하지 않는다. 독립 검증과 실제 결함 수정은 필요한 작업이며, 각 병목이 차지한 정확한 토큰·절감률은 현재 로그로 분리할 수 없다.
개선 순서는 환경 소유권/대기 계측 → 변경에 맞는 검사 묶음과 완료 알림 → 필요한 규칙 중심의 KB 전달이다. 새 범용 실행기·벡터 DB·추가 skill을 먼저 만들 필요는 없다.

## 1. 수치와 해석 기준

기존 집계 JSON과 읽기 전용 thread_history_1.sqlite를 대조했다. 명령 3,048건을 재집계했고, 선택한 10개 요청의 턴 경과와 명령 수를 확인했다.
4,094개 response_id의 유일성과 응답→요청→전체 사용량 합계를 재검산했다. 원본 rollout 47개 파일의 token_usage_record 4,094건에서 입력·캐시 입력·출력·총 토큰과 thread_id가 집계와 일치함도 대조했다. [공개 가능한 수치 요약](022-log-bottlenecks-summary.json)에 선택 수치·확인 방법·제한을 남겼다. 입력 원본 해시·비공개 trace 링크·원시 기록 식별자는 로컬 전용 상세본에만 보관한다.
원시 대화·명령 본문·도구 출력·인증 정보·비공개 trace 링크는 이 저장소에 복사하지 않았다. 사례 번호 R001 등은 기존 로컬 분석의 순위 표기이며 외부 세션 식별자가 아니다. 로컬 원본이 없는 외부 독자는 수치 간 정합성은 확인할 수 있으나 원시 로그 전체를 독립 재현할 수는 없다.

| 항목 | 값 |
| --- | ---: |
| 요청 수 | 81 |
| 고유 모델 응답 | 4,094 |
| 총 토큰: 캐시 포함 | 589,718,821 |
| 미캐시 입력 | 10,501,945 |
| 캐시 입력 | 577,377,408 |
| 출력 | 1,839,468 |
| 명령 수 | 3,048 |
| 0 이외 종료 코드: 결함 수 아님 | 325 |

총 토큰의 97.91%는 캐시 입력이다. 총 토큰 = 미캐시 입력 + 캐시 입력 + 출력이며, 캐시를 다시 더하지 않는다. 추론 출력도 출력에 포함되므로 중복 합산하지 않는다.
이 수치는 실제 청구액·구독 한도 소모량이 아니다. 모델·캐시·과금 기준별 대조 없이 원화 비용이나 절감 금액으로 환산하지 않았다.

시간은 로컬 턴의 기록된 duration_ms다. 모델 추론 시간·손으로 작업한 시간·플랫폼 전체 완료 시간이 아니다. 병렬 턴의 경과를 더해 전체 작업 시간을 만들지 않는다.
서버·미리보기·에뮬레이터의 긴 실행 수명은 느린 검사 시간과 다르다. 과거 Langfuse LLM 관측의 0초는 시작 시각 부재 때문에 생긴 값이므로 모델 지연 분석에 사용하지 않는다.
일부 과거 가져오기 trace의 끝은 마지막 사용량 시각이다. R084의 로컬 턴 32.68분과 가져온 trace 약 83.86분은 서로 다른 경계이며 같은 지표로 비교하지 않는다.
상태 completed는 로컬 턴 종료 상태이지 전체 제품 인수 성공이 아니다. 분류별 명령 수는 문자열 기반 휴리스틱이며 정확한 단계별 시간은 아니다.

## 3. 병목 1 — 공유 환경 잠금과 뒤늦은 준비 실패

### 관찰한 사실

- R001: 75.42분, 총 92,772,914토큰. 조사/읽기 137건, 검증/빌드 분류 200건.
- 기존 메시지에는 다른 플랫폼의 공용 DB 잠금 대기, 잠금 해제 뒤 포트 충돌, Rust 전용 검사로 전환한 과정이 남아 있다.
- 실제 `.local/flutter-auth-green-01/result.json`: status=blocked, reason=`TimeoutError:Lock deadline elapsed`, 경과 600.011초. 기록된 명령은 build 19.141초 하나이고 suite 결과는 비어 있다.
- 로컬 명령 로그도 해당 시도의 600.111초·종료 1을 확인한다. 프로세스 경과와 보고서 내부 경과는 시작/정리 경계가 달라 약간 다르다.
- 후속 green-02는 377.296초에 passed다. 명령별 기록 합은 50.244초이며 나머지 327.052초는 잠금·준비·정리 등 비계측 구간이다. 전부 잠금 대기라고 확정하지 않는다.
- 두 시도의 소스·검사기·바이너리 해시는 모두 같지 않다. 따라서 후속 재실행을 동일 입력의 불필요한 중복으로 판정하지 않는다.
- R002와 R005에도 공유 잠금 대기가 보인다. R005는 전용 PostgreSQL로 분리한 기록이 있다.

### 원인 판단

잠금 시간 초과는 확인된 원인이다. 현재 fixture 일부는 공유 잠금을 잡은 채 서버가 살아 있는 동안 유지한다. 플랫폼별 미리보기와 검사 수명이 공유 자원 점유와 결합한다.
현재 코드는 과거 실행 이후 수정됐을 수 있다. 코드의 현 구조와 과거 실패를 연결한 진단이지 모든 과거 대기 시간을 소급 측정한 것은 아니다.

## 4. 병목 2 — 검증·상태 확인의 잦은 왕복과 늦은 통합 발견

### 관찰한 사실

- R008: 19.14분·37,639,542토큰·305개 모델 응답. 검증/빌드 분류 명령 123건, write_stdin이 포함된 응답 40개.
- 그 40개 응답의 전체 토큰 합은 5,015,250이다. 대기 도구 자체의 토큰 비용이나 제거 가능한 양이 아니다.
- 전체 81개 요청에서 write_stdin 포함 응답 326개, 그 응답 전체 토큰 49,439,913이다. 총합과 겹치는 부분집합이므로 별도 비용으로 더하지 않는다.
- R002는 검증/빌드 분류 156건. 실제 수명주기 수정 후 전체 UI 검사 385개를 다시 통과한 기록이 있다.
- R008에서는 모의 통신 함수 검사가 놓친 실제 화면 fetch 오류를 수정했다. R003과 R001에서도 인증·화면 이탈 관련 실제 결함을 발견했다. 이 회귀 확인을 일괄 삭제하면 안 된다.

### 원인 판단

많은 검사 명령·상태 왕복은 관측 사실이다. 그중 불필요한 비율은 아직 미확인이다. 긴 작업마다 모델이 상태를 읽고 문맥을 재소비하는 운영, 변경 범위와 전체 검사의 결합, 실제 통신/UI 결함의 늦은 발견을 개선 후보로 본다.
초기 원인 수정 뒤의 재검사와 독립 검증은 필요한 작업이다. 동일 성공 결과 재사용은 소스·기준·환경·목적이 같은지 확인된 경우에만 허용한다.

## 5. 병목 3 — 반복 문서 탐색과 넓은 KB 전달

### 관찰한 사실

- 동일 명령·동일 출력 그룹에서 초기 피드백 README/명세/기록 일괄 읽기가 4회·4개 thread, 과거 구현/비교/흐름 기록 묶음 읽기가 5회·5개 thread 확인된다.
- 같은 `check.py preflight` 출력은 19회·12개 thread에서 재등장한다. 대부분 기록상 매우 짧아서 이 명령 자체를 큰 시간 병목이라고 주장하지 않는다.
- 서로 다른 역할에 필요한 문서는 반복 전달될 수 있다. 독립 검증을 없애야 한다는 증거가 아니라, 역할에 무관한 공통 이력의 전파를 줄일 후보다.
- R041: 41.87분·8,433,080토큰, 미캐시 입력 119,150·출력 79,562. 상세 지식/예제 구축 작업이다.
- R046: 32.37분·7,785,274토큰. 언어별 문서·출처 구축 작업이다.
- 두 작업의 경과 합 74.24분은 턴 경과의 합계다. 지식 구축 투자이며 순수 낭비·병렬 전체 경과·회수 가능한 시간으로 해석하지 않는다.
- 현재 packs.json에는 언어 5·플랫폼 5·상세 묶음 6·묶음별 주제 9개가 있다. 기능 선택 15개에는 F01–F14와 별도 stock-search-price 파일럿이 포함된다.
- 현재 context는 feature 문서·공통 문서·언어 안내·플랫폼 안내·상세 묶음 목차와 기본 8개 주제를 출력한다. WebView는 상세 9개를 포함한다.
