# Android 30분 핵심 기능 구현

시작 2026-10-28 09:39:53 UTC, 목표 종료10:09:53 UTC. 사용자는 기존 Rust 범위의 Android
연결을 요청했고30분 안에 전체가 불가능하면 핵심 기능을 우선하도록 승인했다.
기존 검색·종가·뉴스·환율에 인증/회원·포트폴리오/거래를 추가한다. 전체 앱 완료로 바꾸어 보고하지 않는다.

## 배정과 지식 입력

테스트 android30_tests(sol/medium), 구현 android30_implementation(sol/medium),
독립 검증 android30_validation(astra/high)을 서로 다른 문맥에 배정했다.
root는 기존 앱 탐색·CoreViewModel·Android 외부 브라우저 콜백과 전용 검증 환경을 통합했다.
각 역할에 로컬 KB부터 읽도록 배정했고 필요한 원본만 보완했다. 외부 웹 검색0회.
재사용한 기존 서버의 모바일 PKCE 계약은 spec/flutter/native-auth.md다. 다른 대화가 추가한
Rust 인증 코드를 수정하지 않고 고정 복사본과 실행 파일로 검증한다.

KB의 직접 선행 읽기는 구현 전 수행했다. core-session/core-portfolio/core-ui 입력 패킷의
형식화·해시 등록은 작업 후반에 완료했다. 처음부터 형식화된 입력 게이트로 시작했다고 주장하지 않는다.
패킷·직접 적용 맵·고정 테스트·실제 결과는 experiments/android-native/core30에 보관한다.

## 진행과 검증

1. 독립 테스트15개 작성, 실제 빈 구현 실패 후 기준 고정. 세션7개를 먼저 넘겨 구현 중
   회원/거래8개 기준을 준비했다. JUnit 반환형 오류는 작성자에게 돌려보내 단언 변경 없이 수정했다.
2. 실제105개 JVM 검사 성공: 기존88+신규15+독립 감사의 안전 회귀2개. skip0.
3. 검증자가 발견한 role 허용 범위와 HTTP503 자동 재전송 문제를 별도 red2개로 재현한 뒤
   구현자가 수정하고 전체105개를 재검사했다. 거래 본문을 one-shot으로 표시해 중복 변경을 막는다.
4. 실제 Rust/전용 PostgreSQL13개 성공: 기존10+신규3. 합성 일회용 PKCE 코드 교환,
   프로필/닉네임, 매수·매도·초과매도 롤백·거래 수정/삭제·이력·로그아웃, 계산/CSRF를 포함한다.
   코드/검증자/쿠키/접속 문자열은 기록하지 않았다. 실제 Google 계정 인증 성공을 의미하지 않는다.
5. APK 빌드·기기·Lint 검증은 별도 결과를 따른다. 화면2개는 구현 전에 작성했지만 기기에서
   red로 실행하지 않았다. 최초 자산ID 직접 입력 초안은 원본 종목 검색·선택 동작으로 교정했다.
   구현 전에 수정 이유·구해시·신해시를 보존했고 불확실 거래·요청 횟수 단언은 유지했다.

## 환경 문제와 처리

공유 DB 잠금 대기로 첫 준비가 멈췄다. DB를 생성하지 않은 자기 준비 프로세스만 종료하고,
전용 데이터 디렉터리·포트55449의 PostgreSQL로 분리했다. 다른 공유 DB·그 검사의 잠금은 그대로 유지했다.
첫 전용 실행은 HTTP18091 충돌로 실패해 자기 DB/클러스터를 정리했다. 새 포트18109로 다시 실행했다.
최종 환경은 .local/android-core30-backend-03, 불변 Rust 소스 복사본+자기 실행 파일을 사용한다.
60초 합성 로그인 코드는 검사 직전에 발급하며 로그인 재료는0600 파일에만 보관한다.

## 구현한 핵심과 제한

- 인증: 외부 브라우저 PKCE/state, 고정 native callback 검증, 메모리 쿠키, CSRF,
  GET401 동시 갱신 공유, 로그아웃/늦은 응답 세대 격리. 앱 종료 후 영구 로그인은 제공하지 않는다.
- 회원: 내 정보·닉네임·로그아웃·탈퇴 UI/클라이언트. 실제 계정 탈퇴 전체 인수는 별도다.
- 자산: 국내/미국 종목 검색·선택, 매수/매도, 거래 수정/삭제, 보유 수량·평균가 조정/제거,
  날짜별 거래 이력, 보유자산 평가·수익률 API/화면. 각 기능의 실행 범위는 검증 근거를 따르며
  모든 버튼과 장애 조합을 실행한 것으로 세지 않는다.
- 거래: 처리 중 변경을 막고 응답 유실·잘못된 성공 응답은 결과 미확정으로 표시한다.
  자동 재전송 대신 명시적 내역 재조회를 요구한다. 로그아웃은 계정 초안·이력·조회 세대를 정리한다.
- 원본 웹과 Rust의 평균 매수가0.00 경계 차이는 남는다. 보유자산 디코더의 모든 필드가
  원본과 완전 동치라는 주장은 하지 않는다. GET503의 라이브러리 재시도는 거래 재전송 보장과 구분한다.
- 실제 Google 자격 증명/콜백 운영 환경, release API 주소, 영구 인증 저장, 다른 기기·OS,
  실제 프로세스 종료 복원·접근성 전체 인수는 미검증이다.
- AI·투자 캘린더·통합 검색/콘텐츠·피드백·관리자와 뉴스 나머지 기능은 이번30분 핵심 밖이다.

## 최종 결과

10:03:29 UTC 독립 검증에서105 JVM·13 실제 Rust/DB·10 기기=128개와 APK/Lint를 승인했다.
실제 Google·로그인된 기기→Rust 결합 흐름·전체 앱은 승인 범위가 아니다.
기기 최초 실패는 테스트 작성자의 종목 응답 envelope 오류였다. 원본의 `{stocks:[...]}`로
바로잡고 기존 단언을 유지한 v3를 다시 실행했다. 중간 lock 미작성 환경 실패도 별도 기록했다.

root 최종 검토에서 새 로그인 시작 시 이전 계정 조회/초안이 남을 가능성을 발견했다.
30분 안에 보강하기 위해 별도 테스트 작성자가 격리 기기 테스트1개를 추가하고 독립 검증자에게
red → 구현 수정 → 기존 포함 전체 화면 검사 순서로 넘겼다. 이전128개 승인을 이 보강의
완료로 대체하지 않으며 마지막 별도 결과를 아래에 기록한다.

추가 격리 테스트의 최초 실행은 테스트 URL을 Main thread에서 계산한 도구 오류로 중단됐다.
작성자가 URL 계산만 Main thread 밖으로 옮긴 뒤10:07:20 UTC 실제 이전 계정 profile 잔존을
단언 실패로 확인했다. 그 기준을 고정한 후 새 로그인 시작에서 세션 세대·메모리 쿠키·
회원 조회·보유자산·거래 이력·검색/거래 초안을 정리하도록 구현을 수정했다.
코어 API 동작은 그대로 두고 기기 전체11개와 Lint를 재검사한다.

최종 별도 승인: [validation-final-v2.json](../experiments/android-native/core30/validation-final-v2.json), 10:09:25 UTC.
105 JVM+13 실제 Rust/DB+11 기기=129개 모두 성공, APK/Lint 완료. 시작부터 독립 승인까지29분32초다.
root가 실제 XML과 최종 CoreViewModel 해시를 다시 확인했고 자기 Rust/전용 DB/에뮬레이터를 정리했다.
전체 앱·실제 Google 계정 로그인은 완료가 아니며 [미완료 지도](../spec/android-native/coverage.md)를 따른다.

## 후속 로컬 실행: 뉴스 조회 연결 수정 (2026-10-28)

Android Studio의 기본 실행은 디버그 API 주소 18081을 사용했지만 실제 미리보기 서버는
18109에서 실행 중이었다. 디버그 기본 주소를 `http://10.0.2.2:18109/`로 변경하고
같은 주소를 지정하는 `.run/DAYNOMY_Local.run.xml`을 저장했다. Intent의 주소 재정의는 유지한다.

사용자의 명시적 ADB 재실행 요청에 따라 `:app:assembleDebug` 성공(종료 코드 0) 후
`emulator-5554`에 재설치하고, 주소 override 없이 `am start -S -W`로 재실행했다.
실제 로컬 Rust의 뉴스 GET은 HTTP 200, totalElements 3이었다. ADB로 뉴스 탭을 열어
920002·920001·920003 세 합성 뉴스 제목이 모두 표시되고 기존 조회 오류가 사라진 것을
UI XML과 화면으로 확인했다. 화면은 `.local/android-port-fix.png`에 저장했다.
이번 변경 후 129개 전체 검사는 재실행하지 않았으며 위 과거 승인과 구분한다.
사용자 확인을 위해 미리보기 서버·전용 테스트 DB와 에뮬레이터는 실행 상태로 유지했다.
