# 006 — 독립 기능의 병렬 구현

사용자 요청: 독립적인 에이전트 작업을 동시에 진행해 대기 시간을 줄인다.
뉴스·포트폴리오 계산의 승인된 세 API 샘플 범위를 유지한다. 전체 기능 이식은 아니다.

## 바뀐 구조

- `agents/representative.json`: 작업별 담당 파일·모델, 공통 검토 역할, 동시 호출/수정 제한.
- `scripts/parallel_features.py`: 뉴스/계산 구현 2개 병렬, 검토 슬롯 1개, 전체 모델 호출 상한 2개.
- `scripts/agent_workflow.py`: 호출부가 명시 모델 설정과 호출 시도 횟수를 받는다.
- `scripts/sample_feature_gate.py`: 공유 Spring 포트·전역 설정·빌드 결과·DB 시작/종료를 잠금으로 보호한다.

작업별 독립 복사본으로 미커밋 소스를 보존한다. 직접 모델 API를 호출하는 새 실행기는
만들지 않았으며 Codex CLI를 backend로 사용한다. model=null은 CLI 기본 선택이다.
실제 모델 이름을 모르는데 특정 모델을 배정했다고 기록하지 않는다.

컴파일/검사가 실패하면 리뷰를 호출하지 않고 진단을 구현 담당에게 전달한다.
리뷰 수정 요청도 같은 담당에게 전달한다. 한 작업의 결정 대기/호출 실패가 다른 작업을
중단시키지 않는다. 두 작업 모두 검사·리뷰를 통과한 경우에만 승인된 파일을 합친다.
합친 코드의 실제 44개 비교와 승인본 해시가 일치해야 completed다.

## 한계

AI 구현이 병렬이어도 실제 서버/DB 검사는 직렬이다. 작업별 2회와 통합 1회의 실제 검사가 필요하다.
다른 피드백/DB/원본 비교 스크립트까지 이 잠금에 참여하는 것은 아니다. 함께 실행하지 않는다.
동일 계정의 모델 호출 한도는 공유한다. 429/503은 추가 자동 전송 없이 해당 작업을 blocked로 남긴다.
스케줄러·프로세스 종료 후 재개·전체 서비스 작업 큐·API provider 교체는 포함하지 않는다.
기존 순차 실험과 시작 코드·작업 구성이 달라 이번 경과만으로 속도 배수를 단정하지 않는다.

## 검증 결과

- 합성 조정기 테스트 **21개 통과**. 실제 스레드의 구현 동시 실행·모델 호출 상한 2·검토 상한 1,
  실패/결정 대기의 독립 처리, 자동 수정, 경계 이탈 거절, 오래되거나 부족한 증거 거절,
  승인본 해시 통합, 통합 실패 차단을 확인했다. 모델/DB 성공 증거로 사용하지 않는다.
- 실제 별도 Python 프로세스 2개에서도 gate 잠금의 진입 구간이 겹치지 않았다.
- 명시 모델 ID의 CLI 인자 전달과 병렬 모드의 429 추가 재전송 금지를 모의 호출로 확인했다.
- 기존 조정기 39개·비교기 회귀 5개도 통과했다. 총 65개는 조정/비교 프로그램 검사다.

### 실제 모델·서버 실행 — 전체는 blocked

명령: `python3 scripts/parallel_features.py --demo`, 종료 2.
기존 승인 범위인 뉴스·계산 샘플을 Codex로 보내 실제 실행했다.
원시 기록: `.local/parallel-features/20261021T021036Z-03bf645d/state.json`.

| 단계 | 실제 결과 |
| --- | --- |
| 뉴스 첫 구현 | 68.229초. 별도 세션 `01a15c39-8aca-7b82-b8eb-ef61655fd7ad` |
| 계산 첫 구현 | 52.953초. 별도 세션 `01a15c39-8b18-7773-9fc7-949239f817b0` |
| 동시 실행 | 두 구현 모두 11:10:36.79 KST에 시작. 약 52.95초 동안 겹쳤다. 첫 두 호출 반환까지 약 68.23초 |
| 권한 검사 | 각 작업의 구현 폴더 내부 쓰기 허용/외부 거절, 검토 쓰기 거절 모두 실제 native probe 통과 |
| 계산 후보 검사 | 실제 Spring/Rust/새 PostgreSQL fixture 비교 **44/44 통과**, fmt·Clippy·빌드 통과 |
| 뉴스 후보 검사 | Clippy `manual_div_ceil` 오류로 실패. 리뷰를 생략하고 진단을 뉴스 구현에 자동 전달 |
| 계산 후속 리뷰 | 서비스 429로 실패. 승인 없음 |
| 뉴스 후속 수정 | 서비스 429로 실패. 수정 코드 반환 없음 |
| 전체 판정 | **blocked**. 통합 후보/패치 생성 및 통합 검사를 실행하지 않았다 |

계산 후보의 44개 검사에는 **기존 정상 뉴스 기준 코드**가 들어 있다. 새 뉴스 후보가
원본 비교까지 통과했다고 해석하지 않는다. 각 파일은 501 빈 구현에서 시작했지만,
에이전트는 기존 Rust 기준 코드도 읽을 수 있었다. 사전 구현 없는 새 기능의 시간 실험이 아니다.
설정은 두 구현과 검토 모두 model=null / cli_default였다. 특정 모델명을 추정하지 않는다.

전체 실행은 11:10:36.35–11:11:48.64 KST 약 **72.29초** 뒤 blocked로 끝났다.
구축·테스트 준비 시간은 이 실행 시간에 포함되지 않는다. 미완료 실행의 종료 시간을
기능 완료 시간으로 표현하지 않고, 이전 순차 실험 대비 속도 배수도 주장하지 않는다.
429는 자동 승인 거절이 아니라 모델 서비스의 호출 제한이다. 병렬 실행이 계정 한도를
늘리지는 않는다. 이번 실행은 추가 전송 없이 중단하고 증거와 후보를 보존했다.

실제 확인된 범위는 **별도 구현 세션의 병렬 실행 → 작업별 검사 → 독립 후속 호출 →
호출 실패 시 완료 차단**이다. 성공한 통합 완료 경로는 합성 검사에서 확인했고,
실제 모델로 끝까지 성공하는 실행은 미확인이다.
