# 004 — 구현·검토 에이전트 분리와 자동 수정

- 날짜: 2026-10-21 KST.
- 요청: 실제 구현·검토 에이전트를 분리하고 구현 → 검증 → 리뷰 → 수정을 자동 연결한다.
- 구축 상태: 조정기·실제 CLI 역할·권한 제한·검사·재시도를 구현했다.
- 실행 상태: **저장 누락 발견 → 독립 리뷰 지적 → 자동 수정 → 실제 재검증 성공**까지 확인했다.
  **수정 후 최종 AI 리뷰는 외부 서비스 429로 미완료**다. 전체 성공으로 기록하지 않는다.
- 원래 `app/src/`와 명세는 변경하지 않았다. 후보 자동 반영·커밋·배포는 하지 않았다.

## 무엇을 만들었나

| 구성 | 역할 |
| --- | --- |
| `scripts/agent_workflow.py` | 실제 CLI 호출, 독립 세션 확인, 상태 전이, 소스 가져오기, 제한된 재시도, 완료 판정 |
| `scripts/workflow_gate.py` | 고정한 검사로 실제 Rust 빌드·HTTP·전용 PostgreSQL·재시작·장애 검증 |
| `prompts/worker.md` | 구현 역할의 입력·수정 범위·결과 형식 |
| `prompts/reviewer.md` | 별도 검토 역할의 근거 확인·수정 요청·결정 요청 |
| `scripts/readonly_runner.py` | 컴파일된 Rust 함수 테스트를 OS 읽기 전용 환경에서 실행 |
| `scripts/test_agent_workflow.py` | 실패·누락 증거·결정 대기·반복 제한 등 조정기 단위 테스트 |
| `scripts/test_readonly_runner.py` | 실제 네이티브 프로그램의 파일 변경 차단 확인 |

구현과 검토는 각각 `codex exec`의 새 세션이다. 같은 대화에서 역할 이름만 바꾸지 않는다.
같은 Codex 서비스와 CLI를 사용하며 별도 모델 회사나 별도 설치가 필수인 구조는 아니다.
검사기와 조정기는 AI가 아닌 Python 프로그램이다. 이들을 AI 에이전트 수에 포함하지 않는다.

이 하네스를 만드는 동안 보조 에이전트 2개가 검사기 구현과 조정기 검토·단위 테스트를
나눠 맡았다. 이 보조 작업과 아래의 실제 CLI 실행 증거는 구분한다.

## 권한과 완료 조건

- 구현 역할은 임시 폴더의 `main.rs`, `feedback.rs`, `csrf.rs`만 쓸 수 있다.
  검토 역할은 읽기 전용이다. 같은 권한 프로필의 실제 OS 쓰기 시도로 차단을 확인했다.
- 명세·검사·역할 프롬프트·Cargo 파일·마이그레이션·선택한 원본 29개 파일은 고정한 복사본을 사용한다.
  원본과 복사본 해시가 바뀌면 중단한다. 원래 앱 소스도 바뀌면 중단한다.
- 소스 가져오기에서 파일 추가·누락·심볼릭 링크·하드 링크·디렉터리·과대 파일을 거절한다.
  기존 `#[cfg(test)]` 이하와 크레이트의 `forbid(unsafe_code)`를 보호한다.
- 조정기의 결정적 포맷 정리 후에도 테스트 보호를 다시 확인한다.
- 후보 서버와 Rust 함수 테스트를 OS 읽기 전용 환경에서 실행한다. 컴파일러는 빌드 산출물을 쓴다.
- 실제 명령의 종료 코드뿐 아니라 새 보고서 존재·생성 시각·정확한 사례 목록·누락/skip/실패를 확인한다.
  HTTP/DB 46개와 재시작·장애 4개가 모두 필요하다.
- 검사한 소스·검토한 소스·최종 패치의 SHA-256이 같아야 한다.
- **실제 검사 성공 AND 별도 리뷰 approve AND 미해결 질문 없음**일 때만 `completed`다.
  실패한 검사를 AI의 승인으로 덮을 수 없다.

여기서 “고정한 검사”는 해당 실행의 구현 에이전트가 변경할 수 없는 기준이라는 뜻이다.
검사나 명세 자체가 무조건 옳다는 뜻은 아니다. 최초 기준은 원본과 사용자 결정으로 확인한다.

## 사용과 한계

실행법·상태별 행동은 루트 README의 자동 실행 항목에 모았다.
원시 증거는 `.local/agent-workflows/<실행 ID>/state.json`, 역할별 `events*.jsonl`,
`result.json`, 회차별 `gate/`와 `gated-source/`에서 확인한다.

- 최대 3회 수정, 호출당 240초, 429/503 최대 3번 시도, 명령당 최대 600초다.
- `needs_decision`은 질문을 남기고 멈춘다. 사람이 명세를 확정한 뒤 새 실행을 시작한다.
  자동 예약·서비스 복구 감시·중단 지점 재개는 구현하지 않았다.
- 읽기 권한은 비밀 파일과 완전히 격리하지 않았고, 서버 네트워크는 DB 연결을 위해 열려 있다.
  실험 DB URL 분리는 PostgreSQL 계정의 다른 DB 접근 권한을 차단한 것과 다르다.
  적대적 코드나 운영 비밀을 안전하게 격리하는 실행 환경으로 사용하지 않는다.
- 두 AI가 같은 명세·모델의 오해를 공유할 수 있다. 독립 문맥과 실제 검사는 위험을 줄이지만
  모든 입력·제품 의도·운영 배포의 정답을 보장하지 않는다.
- Spring 비교 50개는 이전 별도 실험이다. 이번 각 회차에서 다시 실행했다고 주장하지 않는다.
