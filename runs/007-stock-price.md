# 007 — 테스트 작성 역할을 분리한 최근 종가 조회

요청: 이전 작업은 커밋하고, 제안한 구조로 다른 API를 구현·실험한다.
기존 하네스·명세·샘플·증거는 로컬 커밋 `ab4cac0`에 보존했다.

대상: GET `/api/stocks/{assetId}/price`. 명세 `spec/stock-price.md`.
API 하나이므로 구현 슬롯은 1개다. 테스트 작성 1개·구현 1개·검토 역할 1개를 구분한다.

- 테스트 작성: 원본 발췌·명세에서 기대값과 Rust 테스트를 먼저 만든다.
- 구현: 별도 문맥과 쓰기 폴더에서 기능 모듈만 작성한다.
- 프로그램: 컴파일·실제 테스트 실행·결함 주입·원본 HTTP/DB 비교를 담당한다.
- 리뷰: 구현·테스트·실행 근거를 읽고 승인/수정 요청한다. 쓰기는 거절한다.

테스트 작성 시점에는 후보 구현이 501 stub이다. 이는 시간상 독립성이며, 전역 파일 읽기를
적대적으로 격리한 것은 아니다. 테스트 unsafe 금지·모듈 경로·일반적인 직접 I/O 금지 표현을
검사하고 실제 실행은 읽기 전용·네트워크 차단으로 수행한다. 정적 검사는 완전한 Rust 분석기가 아니다.
컴파일은 조정기가 고정 Cargo/기존 캐시 의존성으로 수행한다.

모델은 각 정의의 model 값으로 선택한다. 현재 null은 CLI 기본 선택이다. 직접 모델 API 실행기가 아니다.
테스트 컴파일/형식 오류도 작성 담당에게 최대 3회 전달하고, 구현 오류·테스트 실패·HTTP 차이는
구현 담당에게 최대 3회 전달한다. 기준 자체가 틀린 문제는 임의로 완화하지 않는다.
429/503에서 자동 반복 전송하지 않는다. 상태와 실제 확인 범위는 실행 후 기록한다.

## 결과

최종 상태는 **범위 내 API 구현·독립 테스트·실제 원본 비교·독립 리뷰 완료**다.
단독 CLI 자동 흐름은 중단됐고, 아래 앱 서브에이전트 연결 경로로 마무리했다.

첫 실제 실행 요청은 자동 승인 검토에서 거절됐다. 신규 API의 원본·명세·후보 코드 전송에
대한 구체적 동의가 없다는 이유였다. 이 요청에서는 Codex 프로세스가 시작되지 않았다.
필요한 전송 범위를 설명하고 별도 승인을 요청했다. 이전 피드백/뉴스/계산 승인을 확대 해석하지 않았다.

사용자가 신규 API 코드·명세 전송 및 실제 에이전트 실행을 명시 승인한 뒤 진행했다.

### 보존한 시도와 실행 경로

1. `.local/stock-price-workflows/20261021T031515Z-047e7729/`: 실제 CLI 테스트 작성자가
   Rust 테스트 11개를 작성했다. 구현 전 501 stub에서 11개 모두 실제 실패했다.
   구현 역할은 별도 CLI 문맥으로 실행됐으나 허용 파일 대신 `src/stock_price.rs` 하위 경로를
   새로 만들어 산출물 경계 검사에서 거절됐다. 후보에 반영하지 않았고 상태는 blocked다.
2. `.local/stock-price-workflows/20261021T031752Z-ea9e5e79/`: 이전 테스트를 변경 없이
   재사용하고 빈 구현의 실패를 다시 확인했다. 경로 지시를 명확히 한 구현 호출은 서비스 429로 실패했다.
3. `.local/stock-price-workflows/20261021T031946Z-65156c2f/`: `desktop_bridge`를 명시 선택했다.
   Python 실행기가 역할별 request.json을 만들고, 현재 대화가 실제 앱 서브에이전트를 배정한 뒤
   응답 JSON을 전달한다. 테스트·실제 비교·수정 반복·완료 판정은 같은 프로그램이 수행한다.
   이 경로는 앱 대화의 배정이 필요하며 단독 CLI 무인 실행 성공으로 표현하지 않는다.
   최초 단위 테스트는 11개 통과했으나 실제 HTTP에서는 가격 없음 등 6개 요청이 404 대신
   200 {}였다. 마지막 결함 주입 `invent_missing`과 같은 응답이었다. 공유 Cargo target에서
   변형 바이너리가 재사용된 정황과, 뒤의 실제 격리 재검사 성공을 함께 기록한다.
   불필요한 구현 수정을 막기 위해 대화 Codex가 대기 중이던 이 실행기를 종료했다.
   원래 state.json을 성공/실패로 다시 쓰지 않았고 `controller-interruption.json`에 중단을 기록했다.
4. `.local/stock-price-workflows/20261021T032402Z-67ebf2cf/`: 기존 코드·독립 테스트를 변경 없이
   가져와 빈 구현 실패 확인부터 전부 재검사했다. 원본은 실행별 target, 각 변형은 해당
   복사본의 target으로 분리하고 테스트 실행 파일 경로도 확인했다. HTTP도 같은 원본 target을
   명시해 실행했다. 마지막 별도 앱 리뷰 승인 후 `completed`, 종료 0이다.

`desktop_bridge`의 에이전트 도구는 앱 권한을 상속한다. CLI의 OS 쓰기 제한이 적용됐다고
주장하지 않는다. 역할 지시·산출물 파일 목록·기반 코드/고정 테스트 해시 검사로 반영 경계를
확인한다. 구현과 리뷰는 실제 별도 앱 에이전트/문맥으로 실행한다. 모델은 앱 설정을 상속하며
역할별 명시 모델을 배정했다고 표현하지 않는다.

### 해석과 남은 범위

- 최초 CLI 시작 12:15:15 KST부터 최종 리뷰까지의 과정에는 경로 지시 수정, 429,
  대화의 배정·원인 조사·빌드 격리 수정이 포함된다. 함수 작성 시간만으로 API 완료 시간을 추정하지 않는다.
- 마지막 재검사는 이미 작성된 코드·테스트에서 출발했다. 새 기능을 처음부터 만든 속도로 표현하지 않는다.
- 테스트 작성자도 틀릴 수 있으므로 고정 기대값, 원본 실제 비교, 결함 주입, 별도 리뷰를 함께 사용했다.
  4개 결함 탐지는 모든 결함을 잡는다는 보장이 아니다.
