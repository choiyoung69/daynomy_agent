# staff 실제 뉴스의 로컬 Docker DB 반영

2026-11-04, Issue [#36](https://github.com/choiyoung69/daynomy_agent/issues/36).
사용자가 staff.daynomy.com의 실제 뉴스를 현재 로컬 Docker DB로 SQL로 가져오도록 요청했다.
선행 로컬 실행·RSS 입력은 [#32 / PR #33](https://github.com/choiyoung69/daynomy_agent/pull/33)이다.

## 원인과 적용

적용 전 로컬에는 한국경제 RSS 제목·링크·대표 이미지와 본문 안내문만 있는 뉴스 50건이 있었고,
키워드·시장 분석은 각각 0건이었다. 앱 코드 수정 없이 데이터를 반영했다.

staff 사이트에 접속해 최신 뉴스가 표시됨을 확인한 뒤, 인증정보 없이 공개 GET API를 수집했다.
`/api/news?page=1&size=100`의 전체 발행 122건을 두 페이지에서 확인하고 각 상세·키워드·시장 분석을 읽었다.
운영 DB·관리자 쓰기·회원 데이터·AI 생성은 사용하지 않았다.

한 SQL 트랜잭션으로 로컬 Docker의 검증된 loopback `_test` DB에 다음을 반영했다.

| 항목 | 반영 결과 |
| --- | --- |
| 발행 뉴스 | 122건: 본문·제목·분류·원래 발행시각·출처·이미지 메타데이터 |
| 이미지 URL | 119건. 원본에서 없는 3건은 그대로 유지 |
| 키워드 | 584건: 순서·분류·정의·기사 속 의미·확인할 점 |
| 시장 분석 | 48건: `risk`·`watchPoint`. 원본에 없는 74건은 생성하지 않음 |
| 기존 RSS 안내문 | 백업 후 50건을 `DRAFT`로 보존. 본문·출처·ID 등은 보존 |

원격 ID를 로컬 뉴스 ID로 덮어쓰지 않고 `local_staff_news_import`에서 대응시켰다.
원본 응답별 SHA-256과 수집시각을 함께 저장한다. 동일 스냅샷 재적용은 기존 행을 보존하며,
기존 원격 ID의 응답 해시가 달라지면 자동 덮어쓰기 대신 트랜잭션을 실패시킨다.

공개 API에 없는 시장 분석 내부 `summary`는 필수 컬럼 제약 때문에 빈 문자열로 두었다.
`observed_fact`·`interpretation`·`limitation`과 관련 종목 연결은 추정하지 않았다.

## 검증과 재현 자료

- DB 122건의 본문·출처·이미지 메타데이터·발행시각, 키워드 순서와 내용, 분석 유무와 내용을 수집 응답과 대조했다.
- 실행 중인 로컬 Rust API에서 상세·키워드·분석 366회 및 목록 두 페이지를 대조했다.
  분석 없음 74건의 404도 확인했다. 목록에는 실제 발행 122건이 나오며 오늘 뉴스는 4건이다.
- 같은 SQL을 다시 실행한 뒤 뉴스·키워드·분석·ID 대응표의 전체 행과 시각이 바뀌지 않음을 확인했다.
- 백업한 기존 50건은 상태·수정시각 외 모든 필드가 보존됨을 확인했다.
- 앱 코드·인증·스키마 마이그레이션은 변경하지 않았으며 빌드·기기 검사는 실행하지 않았다.
  화면 표시와 네이티브 이미지 다운로드는 이번 검증에 포함하지 않는다.

Git 제외 `.local/staff-news-import/`에 `snapshot.json`, `before.json`, `import.sql`,
`capture-result.json`, `apply-result.json`, `verification.json`과 일회성 수집·적용·검증 스크립트를 남겼다.
스냅샷과 SQL은 공개 Git 기록에 복제하지 않았다. 최초 SQL 적용은 2026-11-04 09:46:58 UTC,
검증 완료는 09:47:53 UTC다.

- 스냅샷 SHA-256: `171eb523ff3d249f73d22015a23fd4dbc00f9dacf6524874a362ea451c8c29b4`
- 실행 SQL SHA-256: `9aa7a145c79775bb61bd5bd8b0057ead408f531c8fae6ae338643be6cacae2a5`

최신 대응 예: staff `/news/295` → 로컬 `/api/news/102`.
원본 뉴스 내용의 사실성을 별도로 검증한 결과가 아니라, 공개 응답의 이관 정확성을 확인한 결과다.
예약 동기화는 추가하지 않았으므로 이후 staff 변경이 자동 반영되지는 않는다.
