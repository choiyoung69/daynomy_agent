# 원본 웹 포트폴리오 — 공통 UI 출발점

2026-11-04 · [Issue #15](https://github.com/choiyoung69/daynomy_agent/issues/15) · 사용자 확정 공통 기준(2026-11-04). 새 스타일을 만들지 않고 `reference/2026-DAYNOMY-dev/frontend`를 재사용했다. 다섯 앱 구현·전체 기능 검증은 후속이다.

## 실제로 보여준 상태

같은 `/` 포트폴리오의 **비회원·보유 자산 없음** 상태다. 원본 안내 팝업만 UI에서 닫았다. 0원은 빈 자산 상태의 원본 표시이며 시세·수익률 예시를 주입하지 않았다. 원본 사용 가이드/랜딩의 `ProductMockup` 예제 데이터는 이번 이미지에 사용하지 않았다.

원본 `src`·`public` 176개 파일을 그대로 복사했고 원본 및 복사본 SHA-256이 모두 일치했다. 바꾼 것은 별도 미리보기의 Vite 설정뿐이다. `.env`는 복사하지 않았고 `/api`·인증 경로는 미리보기에서 503을 반환한다. DB·백엔드·AI·예약 작업을 실행하지 않았다.

## 공통 정보구조와 흐름

- 원본 관찰: 브랜드/검색/로그인 → 포트폴리오·소식·투자 리그. 현재 WebView의 세 번째 항목은 투자 캘린더이므로 원본과 구분한다.
- 공통 출발점: 포트폴리오를 중심으로 자산 요약 → 자산 분석 → 보유 자산/거래 내역 → 관련 소식 순서를 유지한다. 로그인은 읽기 시작 전의 필수 단계로 만들지 않는다.
- 핵심 기록 흐름: 거래 기록 → 종목 검색·국내/미국·주식/ETF → 거래 필드 입력 → 명시적 저장 → 결과 확인. 이번에는 입력 창 진입과 취소 복귀까지만 확인했다.
- 리그는 제품 제외 범위다. 원본 증거 이미지의 링크를 제품 활성 메뉴로 이식하지 않는다. 투자 캘린더의 슬롯은 명세에 두되 대상 클라이언트의 준비 상태를 확인한 뒤 노출한다.
- AI·콘텐츠/인물은 향후 연결 지점으로만 관리한다. 준비되지 않은 플랫폼에 활성 버튼이나 정상 결과를 만들지 않는다. 관리자와 F14 이메일 알림은 이번 사용자 탐색 설계에서 확장하지 않는다.

| 영역 구분 | 흰 표면, 얇은 구분선, 요약 숫자의 크기 차이. 자산 추이·구성은 원본의 둥근 테두리 패널. 새 카드나 장식 그림을 추가하지 않는다. |

| 760px 이하 | 헤더 간격과 주요 배치 축소. 자산 대시보드 그리드 1열 전환 |
| 720px 이하 | 제목 22px, 포트폴리오 상단 padding 28px |
| 640/620/420px | 거래 내역·요약·도구 영역의 세부 재배치. 620px 이하 헤더 32px+20px 두 줄, 페이지 행동 버튼은 한 줄에서 균등 폭 |
| container query | 대시보드 내부 가용 폭에 따라 표·차트가 바뀐다. 화면 너비만으로 모든 배치를 결정하지 않는다. |

1440×1024에서 본문/소식은 약 824/330px, 390×844에서는 본문 318px 단일 열·좌우 여백 36px였다. 두 폭의 문서 가로 너비는 각각 1440/390px로 가로 넘침이 없었다. 중간 경계값 전수 렌더는 하지 않았다.

## 플랫폼 고유 적용점 — 레이아웃을 바꾸는 승인과 별개

| 대상 | 같은 정보·시각 규칙 위에 적용할 관례 |
| --- | --- |
| Android | Compose 의미 역할·TalkBack, 시스템 뒤로 가기, IME와 키보드 가림 처리, 최소 48dp 터치 영역 |
| iOS | SwiftUI NavigationStack/기본 뒤로 가기, Dynamic Type·VoiceOver, 최소 44pt 터치 영역을 프로젝트 기준으로 사용 |
| React Native | 호스트 OS의 뒤로 가기·키보드·접근성 역할/선택 상태·글자 배율을 네이티브에 맞춤 |
| Flutter | 동일 토큰을 Theme/Semantics/SafeArea로 연결. 기존 NavigationBar/Rail을 바꾸는 작업은 다음 적용 단계에서 결정 |
| WebView | 현재 원본 반응형을 그대로 기준으로 유지. DOM 의미·포커스 복귀·브라우저/호스트 뒤로 가기를 연결하고 네이티브 헤더를 중복하지 않음 |

48dp는 [Android 접근성 지침](https://developer.android.com/guide/topics/ui/accessibility/views/apps-views), 글자 확대와 iOS 기본 터치 크기는 [Apple 접근성 지침](https://developer.apple.com/design/human-interface-guidelines/accessibility)을 근거로 한다. 일반 본문 대비 4.5:1·큰 글자 3:1은 [WCAG 기준](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)에 맞춰 이식 후 실측한다. 이번 원본 재현을 접근성 인증으로 표현하지 않는다.

## 출처·충실도·검증 한계

직접 근거: `src/index.css`, `src/App.css`, `src/features/navigation/ServiceHeader.{tsx,css}`, `src/features/portfolio/PortfolioPage.tsx`, `portfolio.css`, `portfolioLedger.css`. 파일별 원본 경로와 해시는 [sources.json](sources.json)에 있다. 금융 상태 규칙은 [서비스 F03–F05](../../../spec/service.md#f03--종목가격환율)를 따른다.

검증 결과: 원본/복사본 176개 동일, 두 뷰포트 실제 렌더 확인, 가로 넘침 없음, 금액 숨김/복원·거래 입력 열기/닫기 확인, 확인 시 브라우저 console error 0개. 원본 메뉴·자산 요약·잠금·빈 목록·비활성 AI가 두 폭에서 동일한 정보로 유지됐다.

실서비스 원본의 별도 스크린샷과 픽셀 차이를 계산하지 않았다. 원본 코드와 자산을 동일 브라우저에서 실행한 근거이며, 운영 데이터·글꼴 설치 차이·로그인·실제 시세·저장·AI·보유자산이 있는 표·기기 접근성·다섯 앱은 미검증이다. 기존 앱 완료나 새 기능 완료를 주장하지 않는다.

시간/사용량·실패·실험 판단은 [기존 기록의 실험 4](../../time-token-experiment.md#실험-4--새-채팅에서-기존-웹의-반응형-시안-만들기)에만 기록한다. 사용자가 원본 웹을 공통 기준으로 확정하고 첫 적용 대상을 Android 포트폴리오로 지정했다. Android 적용은 원본의 시각 규칙을 유지하면서 플랫폼 입력/탐색/접근성 관례와 현재 구현 범위를 따른다.

## Android 첫 적용

[Android 적용 계약](../../../spec/android-native/portfolio-design.md) · [기본 대시보드](android/portfolio-dashboard-empty.png) · [거래 입력](android/portfolio-trade-editor.png) · [부분 평가](android/portfolio-partial-valuation.png) · [가로 화면](android/portfolio-landscape.png)

화면 이미지는 API33 에뮬레이터의 명시적 합성 데이터 인수 검사에서 캡처했다. 원본과 나란히 확인해 흰 표면·검정 주요 동작·청색 강조·pill 버튼·요약 순서를 유지했다. 거래 입력의 초기 스크롤과 선택 칩 색상 차이는 비교 후 보정했다.

차이: 기존 Android의 종목/뉴스/환율/자산/계정 탐색을 유지하고 포트폴리오에서만 같은 토큰을 적용한다. 회원 포트폴리오만 실제 연결하며 웹의 게스트 임시 저장은 제공하지 않는다. 수익률 그래프 대신 실제 응답의 텍스트 조회, 비중 그림 대신 실제 평가 응답의 종목별 수치를 표시한다. 보유 종목 뉴스는 준비 중이며 AI·리그는 활성 메뉴로 추가하지 않는다. 플랫폼 글꼴·48dp 터치 영역·시스템 뒤로 가기·IME·글자 확대를 사용하므로 웹과 픽셀 단위로 같다고 표현하지 않는다.

## 사용자 확정 탐색 수정 — 하단 3탭과 상단 검색

공통 셸은 **상단에 항상 보이는 검색창 → 독립 본문 → 하단 네비게이션**으로 정한다. 하단 탭은 **포트폴리오·이슈·내 계정** 세 개이며 리그는 넣지 않는다. 이는 원본 관찰 이미지와 구분되는 사용자의 명시적 수정 결정이다. Android에 먼저 적용하고 다른 클라이언트는 후속 적용한다. 현재 검색은 실제 구현된 종목명/코드 검색이며 통합 검색으로 오인시키지 않는다. 종목과 환율을 별도 하단 탭으로 남기지 않고 각각 상단 검색과 내 계정의 보조 경로로 연결한다.

## 승인 이미지의 실제 Compose 구현 — PR #19

[승인 시안](concepts/portfolio-v1.png) · [최종 실제 Compose 캡처](android/approved-normal.png) · [글자 200%](android/approved-font200.png) · [검증/해시](android/verification.json)

상단 검색·제목과 거래 버튼·평가 요약·자산/거래 탭·보유 종목행·아이콘 하단 3탭을 Compose로 구현했다. 위 정상/큰 글자 캡처는 MockWebServer의 명시적 합성 응답(검증용 보유종목 TEST777)이며 실제 계좌·실시간 가격이 아니다. 시안 숫자와 다른 값으로 응답 바인딩을 검증했다. 앱 코드에 이미지나 샘플 금액을 넣지 않았다. 실제 실행용 에뮬레이터에는 최종 APK를 설치했으며 서버 응답 상태를 그대로 표시한다.

검증 agent가 탭 왕복 시 숨김 상태 해제와 재평가 실패 후 이전 값 잔존을 발견했고 수정 후 별도 회귀 검사를 통과했다. 최종 시각 대조에서 주요 가로 잘림·겹침·시각적 blocker 없음. 아이콘·한국어 시스템 글꼴·실제 상태/수치 차이는 네이티브 및 데이터 차이다. 실제 서버/OAuth·실기기 TalkBack·태블릿·다크모드는 이번 범위에서 검증하지 않았다.

승인 토큰을 재사용해 기사 목록/상세와 프로필·서비스·계정 관리를 정리했다. 모두 명시적 합성 기사/회원 응답의 캡처다. 정상 포트폴리오의 독립 새로고침 버튼은 제거했으며 오류 상태의 다시 조회는 유지했다. 새 시안 이미지를 제품에 붙이거나 미구현 뉴스 이미지/AI·설정 기능을 추가하지 않았다. 503과 비회원을 구분하며 검증 agent가 로그인 복구 회귀도 별도 확인했다.

## 최신 사용자 교정 — 전역 검색 제거·오늘 뉴스 대시보드

앞선 상단 고정 검색 캡처는 이전 적용 증거다. 최신 화면은 전역 검색창을 제거한다. 이슈 상단에 오늘 뉴스 최신3건/최대9건 펼침을 두고 그 아래 실제 `/api/search/news` 검색을 제공한다. 거래/종목 조회 검색은 `/api/stocks`로 분리한다. 환율은 미국 종목/거래에서 원래 화면으로 복귀하도록 이동했으며 내 계정 메뉴에서는 제거했다.

[현재 대시보드 Compose](android/context-dashboard.png) · [현재 검색 Compose](android/context-search.png). 명시적 합성 HTTP 응답 캡처이며 실제 계좌/발행 데이터가 아니다. Issue #11 검색 구현과 검사를 재사용했고 오늘 뉴스·검색의 실패/빈 상태를 독립 검증한다. 실시간 환율·통합 콘텐츠 검색·뉴스 이미지/AI 구현으로 표현하지 않는다.

## 최신 이미지 캐러셀과 키보드 검색

[실제 사진 캐러셀](android/carousel-dashboard.png) · [실제 API 검색 입력/결과](android/carousel-search.png) · [글자200%](android/carousel-dashboard-font200.png)

사용자 제공 트렌딩 예시를 기준으로 오늘 뉴스 API의 imageUrl·제목·분류·발행일을 실제 Compose HorizontalPager에 연결했다. 좌우스와이프·이전/다음·위치 표시·상세/회전 복원, 이미지 로딩/없음/실패를 구분한다. 데이터는 오늘 API의 발행순이며 최근7일 반응 순위가 아니다. 검색 제출 버튼은 제거하고 키보드 검색/Enter로 제출한다.

사진 로딩은 [Coil2.7.0](https://github.com/coil-kt/coil/releases/tag/2.7.0)의 AsyncImage로 요청·디코딩·캐시를 처리하고 기존 Compose BOM의 Foundation Pager를 명시했다. dependency lock에 Coil/전이 의존성과 Okio3.9.0이 반영됐다. 기존 API 세션/쿠키를 이미지 로더에 전달하지 않는다.

캡처의 기사·응답은 명시적 테스트 데이터다. 사진은 원본 웹의 reference/2026-DAYNOMY-dev/frontend/src/assets/news-home-banner.jpg를 **AndroidTest/assets/news-photo-fixture.jpg에만** 복사해 MockWebServer의 실제 image/jpeg 응답으로 제공했다(SHA256 0ac56a098fccb71b1496d92b10e2e8bef19776b522d86e5ad1ffc7914cd9b76a). 원본은 수정하지 않았고 제품 APK에는 이 fixture를 넣지 않았다. 정상 PNG 절대URL·상대JPEG·이미지없음·HTTP404도 구분해 검사한다. 제품에서 임의 기본 사진으로 쓰지 않는다.

## 회원 AI 포트폴리오 분석

[저장 분석 실제 Compose](android/ai-ready.png) · [부분 분석](android/ai-partial.png) · [큰 글꼴](android/ai-ready-font200.png) · [API/상태 계약](../../../spec/android-native/ai-analysis.md)

자산 요약 아래 AI 분석을 펼치면 GET으로 저장 결과를 읽는다. 분석 생성/최신 근거 확인·이력은 기존 회원 API를 명시적으로 호출한다. 이전 성공 보존·null 점수 판단 보류·부분/근거 부족·출처·세션 만료를 구분한다. 캡처는 검증용 합성 AI 응답이며 실제 외부 모델이 생성한 금융 분석이 아니다. 제품에 샘플 결과를 하드코딩하지 않았다.

### 원본 AI 분석 시각 이식 보정

앞선 텍스트 나열 화면을 원본 웹의 도넛·자산 선택 목록·영향 상세·접힌 출처로 교체했다. 위 AI 캡처는 이 보정 결과로 갱신한다. 휴대폰에서는 도넛을 줄이고 순서대로 배치하며, 넓은 화면에는 두 열을 사용한다. 선택만으로 API를 재호출하지 않는다. 전체/종목 출처를 구분하고 서버가 제공하지 않는 일일 잔여 횟수는 표시하지 않는다. 원본 스크린샷을 제품에 넣지 않고 Canvas와 실제 Compose 입력으로 구현했다.

[종목 선택 시 실제 비중·상세 전환](android/ai-selected.png). 합성 테스트 응답의 기기 캡처다.
