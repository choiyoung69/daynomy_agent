# Android 포트폴리오와 React Native 화면 구성 맞추기

관련 [Issue #39](https://github.com/choiyoung69/daynomy_agent/issues/39). 사용자 요청: Android Native 화면을 React Native와 비슷하게 수정한다.

Android 비회원 첫 화면이 긴 검색·입력 폼부터 보여 포트폴리오처럼 읽히지 않던 문제를 수정한다. 제목/종목 담기 → 임시 저장 안내 → 평가금액/매입금액 → 보유 목록 → 평가/로그인 순으로 배치했다. 검색·보유 입력은 별도 진입·닫기·시스템 뒤로가기를 제공하고 실패한 저장은 입력에 남긴다. 입력 초안과 열림 상태는 회전·탭 이동에서 유지한다. 앱 프로세스 종료 뒤 보유 저장은 기존처럼 제공하지 않는다.

비회원은 거래 원장이 아닌 기존 임시 보유 관리이므로 버튼은 ‘종목 담기’로 표시한다. RN의 거래 내역 탭·게스트 영구 저장·자산 추이 기능을 가짜 화면으로 추가하지 않는다. 빈 보유만 0원이며, 보유가 있지만 평가 전/실패이면 ‘평가 필요’를 표시한다. PARTIAL은 평가 가능한 종목 금액으로 표시하며 전체 손익을 정상 합계로 만들지 않는다. 금액 숨김은 요약·평균 매수가·평가 상세까지 적용한다.

공통 흰 표면·검정 행동·청색 선택을 유지하고 22/18/16/14/12sp 위계와 20dp 페이지 간격을 사용한다. 페이지 최대 폭760dp, 48dp 터치와 큰 글자·IME를 유지한다. 하단 바에는 구분선을 추가하고 이중 시스템 inset을 제거했다.

기반은 origin/main `8ab8a55a`. `.local/native-density`의 기존 미커밋 Android 스타일 4파일을 복사해 통합했다. 원래 작업 폴더·RN 파일은 수정하지 않았다. 읽은 RN 기준은 같은 폴더의 App.tsx·theme.ts 및 `.local/rn-android-parity`의 실제 기기 캡처다.

KB는 원본을 가진 루트 체크아웃의 `.local/android-rn-ui/knowledge/core-ui/manifest.json`을 준비해 5문서를 읽고 원본 PortfolioTransactionEditor·portfolioHoldingsStorage와 대조했다. 별도 worktree의 준비는 Git 제외 reference가 없어 실패했으며 통과로 세지 않는다. 출처가 있는 루트에서 최종 verify를 수행한다.

검증 결과는 최종 PR에 기록한다. 실제 OAuth·Rust/DB 연결·실기기·TalkBack·태블릿·프로세스 종료 복원은 이번 검사 범위에 포함하지 않는다. 구현자가 검사를 실행하므로 별도 검토자의 독립 리뷰로 표현하지 않는다.

검사: Kotlin/JVM154개(실패·skip0), API33 ARM64 회원/비회원/셸17개 통과. 이후 비회원 2개에 오입력·미평가·마스킹·탭 복귀 단언을 추가하여 기본·200%·실제 가로에서 각각 통과했다. 최종 자산 탭은 큰 글자에서 ‘내 자산’으로 줄여 한 글자만 다음 줄에 남는 현상을 보정했고 관련2개·APK·lint가 통과했다. 성공한 JVM 전체는 반복하지 않았다. 최초 신규 대시보드 검사는 수정 전 실패했다.

초기 가로 시도는 시스템 설정이 캡처에 적용되지 않아 가로 검증으로 세지 않았다. 테스트 Activity에 방향을 명시한 실제 가로 2개는 통과했다. 회전 애니메이션 중 찍힌 최초 캡처는 안정화 대기를 추가해 관련1개만 다시 생성했다. 합성 데이터이며 실거래·실제 시세 캡처가 아니다. 기본3장·큰 글자2장·가로2장은 screenshots/에 보존한다.
