# 남은 결정과 검증

| ID | 남은 질문 | 현재 상태와 다음 확인 |
| --- | --- | --- |
| Q01 | 첫 이식 기능과 최소 OS·언어·프레임워크 버전은 무엇인가? | 지식 범위는 F01–F13과 F14 보류 경계까지 확장. 첫 앱 구현 기능·정확한 OS/SDK/의존성 버전은 미정. |
| Q02 | baseDate는 플랫폼별로 어떻게 날짜를 보존하는가? | 원본 DTO는 LocalDate, 웹은 문자열 검사. Node에서 날짜의 시간대 변환 시 전날 표시를 재현. 각 앱 날짜 보존·달력 검증 정책은 미정. |
| Q03 | ID·십진수·반올림·표시 규칙은 무엇인가? | 웹의 안전 정수·유한수 검사와 서버 BigDecimal을 구분. 다섯 언어의 경계·JSON·금액 예제 실행(DX09). 앱 디코더 연결과 실제 업무 반올림 정책 검증은 미확정. |
| Q04 | 늦은 검색 응답·화면 이탈·수동 단가 보존이 실제로 같은가? | 원본 코드에 취소·보존 분기가 있음. UI·대상 앱 실행 미검증. |
| Q05 | 앱의 인증·쿠키·토큰·로그인 복귀를 어떻게 연결하는가? | 웹 request의 쿠키·401 갱신은 정적 확인. 네이티브·WebView 계약은 별도 조사 필요. |
| Q06 | 위키가 정확성을 유지하면서 다섯 구현의 검증 완료까지 전체 시간을 줄이는가? | 사용자 목표에 시간 단축 추가. 고정 질문과 실제 구현 비교는 미실행. 초기 구축 시간은 미계측이며, 준비·병렬 경과·통합·검증·재작업·갱신을 구분해 기록. |
| Q07 | Spring과 Rust 검색어 처리의 Unicode 경계가 같은가? | 실행 예제에서 NBSP strip/trim 차이 확인, EM SPACE는 동일. 실제 HTTP/SQL 검색 결과 대조는 미실시. |
| Q08 | 플랫폼별로 착수 전에 준비할 지식과 전달 순서는 무엇인가? | 공통·기능 14개·언어/플랫폼 진입점과 상세 패키지 6개/주제 54개를 선택/범위 검사에 연결. 지식 구조 범위는 채웠고 대상 버전·실제 어댑터·실행 준비는 미완료. |
| Q09 | 오류·재시도·취소 계약을 각 대상에서 어떻게 확인하는가? | 첫 공통 주제에 표준·원본 관찰·설계 제안·실행 사례를 정리. 실제 HTTP 클라이언트의 취소·401·시간 제한·재시도 정책과 fixture는 미정. |
| Q10 | 거래 중 통신 단절·중복 전송·동시 수정은 어디서 보장하는가? | 포트폴리오 거래의 서버 트랜잭션·잠금과 기존 검사 소스를 정적 대조. 실제 DB 재실행·커밋 응답 유실·중복 방지 계약 확인은 남음. |
| Q11 | 현재 호스트로 다섯 앱을 빌드할 수 있는가? | 독립 언어 예제 5종 실행. Kotlin/Dart/TS SDK는 .local에 격리. 활성 Xcode/시뮬레이터·Android/Flutter 앱 빌드 환경은 별도 준비 필요. 대상 버전·앱 빌드 명령 미정. |
| Q12 | 외부 원문을 고정하고 변경을 위키에 어떻게 반영하는가? | 등록 출처를 63개로 확장해 모두 보관·확인 범위 기록·기준 지정. 예약 갱신·의미 검토 자동화는 미구축. |

질문을 해결하면 결정 근거·적용 범위·관련 문서·실행 증거를 추가하고 상태를 바꾼다.
과거 미결정 기록과 잘못된 설명의 수정 이력은 [작업 이력](log.md)에 보존한다.
