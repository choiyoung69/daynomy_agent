# 첫 구현 실행 요청

> 보관용: 첫 구현에 사용한 요청문이다. 해당 구현은 완료했으며 결과는
> [첫 구현 기록](../runs/002-implementation.md)에 있다.
> 현재 작업 지시로 자동 재실행하지 않는다.

이 저장소의 AGENTS.md, README.md, spec/feedback.md, runs/001-setup.md를 읽고
비회원 피드백 등록을 Rust로 구현하라. 원본을 읽고 명세의 근거를 필요할 때 확인하라.
구현 위치는 app/이다. reference/는 수정하지 마라.

먼저 preflight를 실행하고 환경 누락과 명세의 미결정 사항을 확인하라.
웹 프레임워크 없이 개별 라이브러리를 조합하고 직접 의존성과 용도를 기록하라.
HTTP 파서를 직접 만드는 것은 요구사항이 아니다. 자체 Rust 코드에서는 unsafe를 금지하라.

POST /api/feedback와 필요한 GET /api/auth/csrf, PostgreSQL 저장을 구현하라.
로그인·관리자 API·UI·다른 도메인은 구현하지 마라. 명세의 CSRF, Java 문자열 길이와
strip 차이, 검증 순서, 실패 시 저장하지 않는 조건을 보존하라.

전용 로컬 테스트 DB를 준비하고 실제 HTTP/DB 검증을 실행하라.
DB는 DATABASE_URL, 서버 포트는 PORT 등 문서화된 설정으로 지정할 수 있게 하라.
운영 정보 없이 새 로컬 테스트 환경을 재현할 실행 방법을 app/README.md에 남겨라.
원본 V25에 필요한 스키마만 사용하고 전체 Spring DB를 복제하지 마라.

구현 → 검사 → 실패 분석 → 수정 루프를 수행하라.
python3 scripts/check.py verify와 명세의 수동 검증 항목을 실행하라.
현재 검증 파일을 수정해 억지로 통과시키지 마라.
환경 문제는 기능 오류와 구분하고, 원인을 해결할 수 없으면 구체적인 상태를 기록하라.
내부 구현 선택은 자율적으로 진행하되, 핵심 외부 동작을 바꿔야 할 때만 질문하라.

runs/002-implementation.md에 시작/종료, 시도, 실제 검증 결과와 종료 코드,
사람 개입, 미검증 항목, 다음 작업을 기록하라. 측정할 수 없는 비용·토큰은 미측정으로 적어라.
최종 보고에는 기능 완료 여부와 남은 제약을 구분하라.
